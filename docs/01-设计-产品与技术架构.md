## 0. 摘要

**一句话**：框一块屏幕区域 → 你在游戏里弹 → 实时判键 → 生成谱子 → 在编辑器里试听微调 → 导出 tick 谱或 BetterGI 脚本。

| 项 | 结论 |
|---|---|
| 核心链路 | **逐帧截取 → 内存分析 → 只存 21 键 RGB 时序（不落图、不编码视频）** |
| 截图方案 | 多后端 + 自动测速 + 失败回退；**屏幕区域 → DXGI**（任意子矩形），**窗口模式 → WGC**（排除自身 HUD）；GDI/PrintWindow 兜底 |
| 一期范围 | 无延音 5 乐器（全 21 键、全有 mp3）+ 识谱 + 播放器 + 编辑器 + tick/BGI 导出 + 打包；**识别源含游戏窗口与浏览器视频** |
| 体积 | 不限；PySide6 + OpenCV + 捕获后端，onedir 约 250–350 MB |

# 第一部分 · 产品

## 1. 功能设计

### 1.1 功能清单

| 模块 | 一期 | 二期 |
|---|---|---|
| 屏幕捕获 | **任意屏幕区域**（游戏 / 浏览器视频 / 播放器 / 任意窗口）+ 16:9 锁定 + 配置档；窗口模式用于排除遮挡 | 自动识别视频内容区（去黑边）、被遮挡/最小化捕获 |
| 键位标定 | Hough 自动 + 手动点选兜底 + 网格吸附 | 自动乐器识别（HSV 模板打分） |
| 识谱 | 无延音 21 键（5 种乐器） | 延音乐器（谐律键琴/跃律琴）+ 14 键（晚风圆号/沃雅妮莎） |
| **播放预览** | **三类格式读取 + 采样音频播放（变速/循环/定位/当前和弦高亮）**；读入 BGI midi / yuanqin 时按谱面所标乐器自动裁剪延音（无延音乐器不带 `A[ms]`，未标乐器按风物之诗；v0.1.6 修复） | 14 键乐器的 MIDI 预览 |
| **按键演奏** | **谱面直接按键注入游戏（v0.1.6）：前台 SendInput 扫描码 / 后台 PostMessage 双通道（通道由 `instruments.json` 的全局 int 参数 `key_play_channel` 定，0=后台 默认，界面无切换按钮）+ 全局起播延迟（默认 3s 倒计时）**；被挡逐拍跳过不中断、回焦补发抬起 | 自动对谱（边听边对） |
| **编辑器** | **语法高亮 / 错误标记 / 播放同步滚动 / 撤销重做 / 另存** | 量化到 BPM 网格、区间替换、批量变换 |
| 导出 | **tick + BetterGI JS** | 风物谱 / Domiso / MIDI |
| 打包 | onedir + Inno Setup | （自动更新可选） |

### 1.2 识别源（不只是游戏）

识别管线的输入被抽象为「用户框选的一块屏幕区域」，不绑定游戏窗口：

| 来源 | 典型场景 | 说明 |
|---|---|---|
| **游戏窗口**（原神） | 自己弹、录制自己 | 最常用 |
| **浏览器播放的视频** | B 站 / YouTube 演奏录像 | **一等公民**；"没有游戏也能转谱" |
| **本地播放器 / 剪辑软件** | 本地录屏、时间轴预览 | 同上 |
| **任意窗口/桌面区域** | 直播画面、远程桌面 | 只要画面可冻结、颜色不失真 |

❌ 云原神（串流压缩，颜色判定不可靠）。两种目标模型见 §5.1。

**视频源特有约束**（UI 必须让用户看到）：

| 事项 | 处理 |
|---|---|
| YUV 4:2:0 有损压缩，颜色漂移 | 按"当前源"独立标定；必要时双模板匹配兜底 |
| 画质增强/插帧/锐化 | 提示关闭；标定以实际画面为准 |
| 播放速度 ≠ 1.0x | 提示用 1.0x；导出时文档标注 |
| DRM 受保护内容 | 连续黑帧检测 → 提示"无法识别" |
| 进度条/字幕/水印 | 框选时避开，或加顶部/底部屏蔽带 |
| 分辨率/黑边 | 16:9 内容区吸附或手动精框 |

### 1.3 已定决策（变更需走 01 更新流程）

| # | 决策 | 落地 |
|---|---|---|
| 1 | 识谱 + 本地谱播放预览 | 产品 = 识谱器 + 播放器 + 编辑器；识别结果**直接进编辑器**，不先落盘 |
| 2 | 一期只做无延音（M4 已实现延音） | 一期 5 乐器全 21 键全有 mp3；数据模型带 `sustain_ms` |
| 3 | 输出 = tick 谱 + BetterGI JS | `formats/tick`（读+写）+ `formats/bgi_js`（写脚本目录） |
| 4 | 优先 16:9，区域可按比例缩放 | 16:9 比例锁 + 分辨率预设；标定在 1920×1080 参考系，运行时按比例映射，**每帧不 resize** |
| 5 | 安装包大小不限 | PySide6 + pyqtgraph，onedir 打包 |
| 6 | 不保留视频留档 | 无视频编码代码、无 ffmpeg 依赖；只有帧与数值 |
| 7 | 识别源 = 任意屏幕区域 | 捕获抽象为 `ScreenTarget`（默认）/ `WindowTarget`（可选）；每源一套配置档 |

### 1.4 核心数据链路（唯一路径）

**逐帧截取 → 内存立即分析 → 只留数值**。每帧拿 `numpy` 数组 → 算 21 键 ROI 均值（21×3 字节）→ 丢弃。链路里没有编解码、没有磁盘写入（数据量 ≈71 B/帧，3 分钟约 0.8 MB）。

| 层 | 内容 | 生命周期 | 默认 |
|---|---|---|---|
| **L0 捕获帧** | BGR `numpy`（区域尺寸） | **1 帧**，分析完即释放 | 常驻内存 |
| **L1 特征序列** | `samples.npz`：`ts[F] float64` + `rgb[F,K,3] uint8` | 会话级 | **必存** |
| **L2 调试快照** | 环形缓冲最近 N 帧 + 一键导出 PNG | 内存滚动，按需落盘 | **关闭** |
| **L3 产物** | tick `.txt` / BGI 脚本目录 / `meta.json` | 长期 | 用户触发 |

- L2 只用于"这一帧为什么判错"的人工复核；UI 标定预览帧是降采样副本（约 480 宽、10–15fps，仅内存）。
- 回归/评测片源必须**无损**（PNG 序列 / FFV1 / x264 `-qp 0`）；`FileBackend` 读 mp4 只验证流程，不用于标定阈值。

## 2. 交互逻辑

### 2.1 三种入口

```
① 实时识谱：框选 → 标定 → 录制 → tick 文本 → 进编辑器
② 打开旧谱：.txt / .dms → 解析 → 编辑器（可试听、可改）
③ 编辑器：试听 → 手改 → 实时校验 → 导出 tick / BGI JS
```

关键点：识别结果**先落编辑器**，听到不对直接改字再导出。

### 2.2 录制主流程

1. **框选区域**：屏幕上拖拽矩形（16:9 比例锁 + 分辨率预设），或"选窗口"入口；
2. **标定向导**：Hough 自动检测 21 键（失败 → 手动点选 + 网格吸附）→ 静默基线 2s → 逐键试按 → 自动求阈值，分离度不足的键标红提示；
3. **录制**：悬浮 HUD 显示实时状态；用户在游戏里演奏；状态栏报 fps / 已识别音数 / 当前按键；
4. **结束**：tick 文本直接写入编辑器文本框（程序写入必须 `blockSignals`），光标停在首个可疑处。

### 2.3 配置档（profile）交互

- 一次标定的全部上下文（区域+乐器+阈值+后端）存成一个档；UI 提供"配置档"下拉 + 复制/重命名/删除；默认自动命名 `<源>-<乐器>`；
- 一键切换"游戏"与"浏览器视频"两套源；**视频源建议单独建档**（阈值更保守）；
- 档里几何量存目标坐标系（屏幕像素或客户端归一化），换分辨率/窗口位置不需重标。

### 2.4 编辑器闭环

```
识别结果 → 编辑器（光标停首个可疑处） → 空格播放 → 听到不对直接改
→ 自动重解析 → 继续 → Ctrl+S / 另存 / 导出
```

- 解析有 Error 时禁用播放并定位到首个错误行；
- 每次切和弦给编辑器发 `(offset, length)` 做高亮 + 自动滚动；
- 打开 fengwu/domiso 旧谱 → 转 tick（带丢失告警）。

### 2.5 HUD 与遮挡策略

| 情况 | 策略 |
|---|---|
| 屏幕区域模式 + HUD 与区域相交 | ①自动把 HUD 移到不遮挡的角（优先）→ ②仍相交则录制期间隐藏 HUD → ③提示改用窗口模式 |
| 窗口模式 | 无需处理（WGC/PrintWindow 不含其他窗口） |

### 2.6 反馈与提示规则

- **后端回退必须说出来**（红字 + 状态栏"（回退）"）；
- 写盘失败等一次性提示走 toast / 状态栏单条消息区（info/warn/error 同位置），不弹窗打断；
- 超快连击（>12 音/秒会漏检）、非 16:9 偏差，均在 UI 与文档写明。

## 3. UI/UX 规范

> **设计源：`design/ui-redesign/`**，本节是与其对齐后的摘要，逐像素规格以设计包为准：
> - `docs/01-设计规范.md` 风格定义与不变量 · `docs/02-设计令牌.md` 色板/字体/几何/对比度实测 · `docs/03-界面规格.md` 逐控件规格 · `docs/04-实施指南.md` 代码落地 10 步
> - `tokens.json`（机器可读令牌）· `templates/theme.py` + `templates/qss.py`（可直接拷入）· `preview/index.html`（可交互视觉基准，5 运行态 × 2 主题）

### 3.1 风格定义：扁平简约的 5 条硬规则

1. **用"面"分层，不用"框"分区**：`bg-canvas`（窗口底）→ `bg-panel`（区块卡/工具栏/状态栏）→ `bg-surface`（按钮/下拉/键位卡）→ `bg-input`（谱面文本框，更暗 = 凹槽）；边框只做 1px `border-subtle` 的最低暗示。判据：**遮住所有 1px 边框，结构依然清晰**。
2. **一个强调色，一屏一处**：`accent` 只允许出现在 **主操作按钮 / 选中态 / 正在播放 / 焦点框** 四种场合；同一运行态最多一个填充式主按钮。
3. **零渐变、零投影，除浮层外**：唯一投影给「手动点选」浮层（blur 24 / y+8 / 28% 黑，日间 14%）。
4. **圆角克制且成体系**：`4` 段内小块 / `6` 控件与键位卡 / `8` 区块卡与浮层；**不允许 2/10/12/16**，同层必须同圆角。
5. **无动画**：主题/态切换瞬间完成，禁用 `QPropertyAnimation`。

### 3.2 颜色只有一个来源（令牌体系）

| 层 | 文件 | 规则 |
|---|---|---|
| 令牌 | `ui/theme.py` | `THEMES["dark"/"light"]` + `OVERLAY`（叠加层，两主题共用）；`_validate()` 导入时校验两表键一致 |
| 样式 | `ui/qss.py` | 唯一 QSS 模板，几何写死、颜色 `{{token}}`；`render()` 残留占位符抛 `KeyError` |
| 绘制 | `preview.py` / `region_picker.py` / `icons.py` / `widgets.py` | 一律 `theme.color(...)` / `theme.overlay(...)`，**禁止 `#hex` 或 `QColor(255,…)` 硬编码** |

- **默认日间**：首次启动 `ui.theme = "light"`（非法值回落日间），切换按钮写 `settings.json`；v2→v3 迁移会把旧档残留的 dark 重置一次。两套主题几何完全同源（同一模板），"切主题不走样"是结构保证的。
- **日间不是夜间反色**：日间底 = 冷白灰 `#F4F6F8`（刻意不用纯白，避免比纯黑更累、与游戏白色 UI 抢注意力），accent `#2563EB`（浅底要"沉"）；夜间底 = 近黑 `#0E1216`，accent `#2A66F0`（深底要"跳"）。**两套主题按同一 4.5:1 对比度标准验收，不存在主/次**。
- **状态色语义两主题共用一套语义、各自取色**：`success`（按下/成功）、`accent`（进行中/选中）、`warn`（注意）、`danger`（错误/收尾）。
- **叠加层不跟主题**：检测圈、采样点、按下高亮、框选遮罩压在游戏画面上，固定在 `OVERLAY`（中性 + 半透明）——"日间主题下的白色检测圈"在雪地场景里不能消失；只有"外框"（预览留白底、header 胶囊、尺寸标签底板）跟主题走。

### 3.4 四档按钮体系与主操作迁移

| 档 | 定义 | 视觉配方 | 控件 |
|---|---|---|---|
| **L0 主操作** | 当前状态下唯一"下一步" | accent 填充 + 白字 | `开始预览` / `学习基线` / `录制谱面`（随运行态轮换，**一屏只一个**） |
| **L1 常用** | 每次开新曲子会用 | surface 底 + 1px 边 | `框选区域` `学习基线` `保存` `打开` `试听` |
| **L2 工具** | 偶尔调、调完不动 | 透明底 + 次级文字，hover 才浮现 | `自动检测` `手动点选` `重置` `16:9` `置顶`、下拉、滑条 |
| **L3 收尾/危险** | 结束进行中的动作 | danger **tonal**（柔和底 + 1px 描边 + 红字，不实心） | `停止预览` / `停止录制` |

**主操作随运行态迁移**（关键机制，`main_window._refresh_action_emphasis()`）：

| 运行态 | L0（accent 实心） | L3（danger tonal） | 其余 |
|---|---|---|---|
| 未标定 / 已标定 | **开始预览** | — | 学习基线、录制谱面禁用 |
| 预览中（未学基线） | **学习基线** | 停止预览 | 录制谱面仍禁用 |
| 预览中 + 已学基线 | **录制谱面** | 停止预览 | 学习基线降回 L1 |
| 录制中 | —（无 L0） | **停止录制** + 停止预览 | 改识别配置的控件整组锁死 |
| 试听中 | —（主操作在控制条） | — | 工具栏整体 L1/L2，不抢戏 |

- 实现只换 `objectName` + `theme.repolish`，**`setEnabled` 时机一行不改**（可用性矩阵与识别流程强绑定，改启用条件必须同步 `docs/03`）。
- 「停止」用 tonal 而非实心红：录制中一屏可能出现两个「停止」，两块实心会盖掉层级；且保持 **实心=推进 / tonal=收尾** 的语法。`重置` 虽清数据但不结束任何进行中状态 → 保持 Quiet，否则红色不值钱。

### 3.5 逐控件规格要点（全表见设计包 `03-界面规格.md`）

| 控件 | 规格 |
|---|---|
| 键位卡 `KeyCard` | 64×64（max 高 88）圆角 6；三行等宽居中：`+1 · Q` 11px/600、RGB 9px、`Δ12` 9px；**Δ 接近阈值（ratio ≥ 0.60）转 warn 琥珀**；按下整卡 `success` 反色（绿底深字，两主题同构，不加投影/光环）；未标定 `state="disabled"` 1px 虚线边 |
| 预览叠加 | 检测圈 1px/55% 白（`MARKER_SCALE=1.6`）；采样点常显但降到 45%、r=max(1.0, 0.07R)（学基线/hover 才提亮，**不能取消常显**——调参刚需）；按下高亮 1.6px 边 + 14% 填充（用户要能看清画面）；header 胶囊 `OVERLAY.chip-bg`（`1069×598 · ×0.52`） |

### 3.6 可用性矩阵与禁用态

- **可用性矩阵（谁能点）一行不改**——档位只决定"长什么样"，不决定"能不能点"，两者分离。
- **禁用 ≠ 变淡**：禁用是"换一套更弱的配方"（底 `bg-surface`、边 `border-subtle`、字 `text-disabled`），不给正常态加 40% 透明度（浅色主题下会糊成一片灰）；**`Primary` 禁用退回 Secondary 的样子**，不留 accent 残影。

### 3.7 文案规范（只改字，不改语义）

`自动检测键位→自动检测`、`重置检测→重置`、`保存文件→保存`、`读取文件→打开`、`播放试听→试听（▶ 图标）`、`停止试听→停止`、`键位状态（未标定时为灰卡）→ 键位状态 + SectionMeta`；说明文字进 tooltip / 占位符 / `SectionMeta`，不进标题。**不改**：弹窗文案、tooltip 原文、`未选择`、`未录制`、`环形（内环）`、`方块（居中）`、乐器名（来自 JSON）。

### 3.8 设计约束、红线与改稿落点

改稿前必读——三条不许破的线 + 既有不变量：

2. **数值必须等宽**：谱面 / RGB / Δ / 状态栏 / 胶囊全部 Consolas，否则跳字。
3. **图标全部运行时自绘**（24 网格 + 4× 超采样，`icons.py`），不引位图/图标字体。
4. **不改可用性矩阵、不改数据契约**（tick 文本语义、谱面 JSON、识别参数）；不做全局热键。
5. 窄窗可用宽 538~700px，优先竖向分组；"暗"是夜间主题的验收要求（底色亮度 ≤ `#1A1A1A` 级别），日间按同一对比度标准独立验收。
6. 反例清单：两个 accent 实心同屏 / 红=进行中 / 渐变发光 / 圆角 10/12/16 / 同层不同圆角 / 等宽换比例字体 / 态切换加动画。

## 5. 接口规范

### 5.1 捕获层

```python
# 两种目标模型
@dataclass(frozen=True)
class ScreenTarget:                       # 默认：任意屏幕区域（跨窗口也行）
    monitor: int                          # 显示器索引（多屏）
    rect: tuple[int, int, int, int]       # 屏幕物理像素 (l, t, r, b)，16:9
    offset: tuple[int, int] = (0, 0)      # 相对显示器原点的偏移

@dataclass(frozen=True)
class WindowTarget:                       # 可选：绑定一个窗口（排除遮挡/HUD）
    hwnd: int
    client_norm: tuple[float, float, float, float]   # 客户端归一化 (u0,v0,u1,v1)

CaptureTarget = ScreenTarget | WindowTarget

class CaptureBackend(Protocol):
    def supports(self, target: CaptureTarget) -> bool: ...
    def open(self, target: CaptureTarget) -> None: ...
    def latest(self, timeout_ms=100) -> tuple[np.ndarray, float] | None: ...
    def close(self) -> None: ...
    def stats(self) -> CaptureStats: ...   # fps / dropped / last_error
```

**目标 × 后端矩阵**

| 目标 | 首选 | 备选 | 说明 |
|---|---|---|---|
| **ScreenTarget**（默认） | **DXGI 桌面复制 + 区域裁剪** | GDI（ScreenDC / mss） | 真正任意区域（WGC 只能抓窗口/整屏，不能抓任意子矩形） |
| **WindowTarget** | **WGC 窗口捕获** | PrintWindow | 能排除自身 HUD、能抓被遮挡窗口 |

**行为规则**：
- **基准测速**：同一 target 类型内比较可用后端（抓 90 帧，评分 = 有效帧率 / 首帧非黑 / 与参考后端一致性），选最高分；跨类型不比较。
- **回退**：连续 20 帧黑屏/超时 → 降级到该类型内的下一名并提示；设置里可锁定后端排障。回退链：`hdr→dxgi→gdi`。
- **互斥**：DXGI 同一输出只允许一个 duplication 会话，与 HDR 后端互斥。

**坐标模型**：
1. `ScreenTarget` 存屏幕物理像素矩形；`WindowTarget` 存客户端归一化矩形（0..1）；
2. 运行时统一换算到"当前帧内的像素矩形"：ScreenTarget + DXGI/GDI 直接用屏幕矩形；WindowTarget + WGC 按归一化比例裁窗口帧；WindowTarget + DXGI/GDI 用 `ClientToScreen` 实时换算；
3. **标定期**把帧缩放到 1920×1080 跑一次 Hough；**运行时**把键位坐标按比例映射回实际帧尺寸直接采样，不做每帧 resize；
4. 帧尺寸/显示器缩放变化 → 重算映射并提示（必要时重标定）。

### 5.2 视觉层

```python
# 标定期：1920x1080 参考帧
roi    = frame[int(h/3):, :]                       # 下 2/3（键区）
gray   = cv2.cvtColor(roi, cv2.COLOR_BGR2GRAY)
mask   = cv2.inRange(gray, 0, 239)                 # 高光挖空 → 琴键成"暗环"
circles= cv2.HoughCircles(mask, cv2.HOUGH_GRADIENT,
            dp=2.0, minDist=80, param1=20, param2=40,
            minRadius=40, maxRadius=53)
# 只把 Y 加回偏移 → 7 个一组 + 行/列均值吸附 → 按 NoteToKeyMap 顺序映射音名
```

> ⚠️ Hough 的 `param1/param2` 正确值与常见默认相反——必须用 **`param1=20/param2=40`**，以运行时配置为准。

**自动阈值标定（录制前，三步）**：
1. 静默基线 2s → 每键 RGB 分布；
2. 逐键试按 → 按下分布；
3. 求解：选分离度最高的通道（`|Δmean|/std`）；`enter = release − 0.55Δ`、`exit = enter + 0.15Δ`；分离度不足的键标红提示；结果按 `(乐器, 分辨率, 皮肤)` 缓存进 `instruments.json`。

### 5.3 时间线

```python
class PressDetector:
    """施密特触发 + 最小按下 + 最小间隔（全部毫秒，帧率无关）"""
```

- 判按参数：`min_hold_ms=25`、`min_gap_ms=30`、`chord_window_ms=25`；
- **延音（M4 已实现）**：`hold >= 乐器 sustain_ms` 时写入和弦的 `sustain_ms`，随谱面文本 `[ms]` 落盘/导出；其余不变；
- 装配：`rest_i = onset_{i+1} − onset_i`，`sustain_i = hold_i`；
- 场景保护：一拍内 ≥ `key_count-5` 个键同时"按下" → 判过场，整段丢弃并 warning。

### 5.4 播放器

- **绝对时间表调度**：`while now < next_t: sleep(min(next_t-now, 5ms))`，抗漂移；
- 音频：`pygame.mixer` 预加载 21 个采样，按下即播，同音重触发先 `stop()`；
- 支持：播放/暂停/停止/定位/循环/变速（0.5–2.0x，采样原速播放，**音高不变**）；
- 回调：每次切和弦给编辑器发 `(offset, length)` 做高亮 + 自动滚动；
- 解析有 Error 时禁用播放并定位到首个错误行。

### 5.6 输出格式

#### 5.6.1 tick（默认）

```
/*
  @name <曲名>
  @instrument <乐器名>
*/
<CHORD>[.<sustain_ms>] <rest_ms> <CHORD>[.<sustain_ms>] <rest_ms> ...
```

- `CHORD` = 连续大写字母（同时按下）；`.sustain_ms` 仅当 `>=50` 输出；
- **GUI 录制文本**用毫秒间隔方言（`A1000F` = 按 A、隔 1000ms 再按 F），延音写在和弦后缀 **`[ms]`**：`A[800]1000F`（v1.35 起；<50ms 不写）。乐器是否延音由 `instruments.json` 的 **`sustain_ms`** 决定（0 = 不延音）；
- **`rest_ms` 必须输出且 ≥1**：tick 解析器会把"没有 Rest 分隔的连续 Chord"合并成一个和弦，生成端必须强制写 rest 才能兼容现有 tick 工具链；
- `rest_i = onset_{i+1} − onset_i`，`sustain_i = hold_i`（与 tick 播放器语义严格对应）。

## 6. 约束、判定标准与性能预算

### 6.1 明确不做 / 已知限制

- ❌ 云原神（串流压缩，颜色判定不可靠）
- ❌ HDR 原生识别（有 j-HDR 后端方案，见 §7.1）
- ⚠️ 超快连击：有效帧率 30–60fps，**>12 音/秒会漏检**（文档与 UI 都要写明）
- ⚠️ 非 16:9：可用但几何有偏差，UI 给警告
- ⚠️ 皮肤改变配色 → 标定向导 + 每（乐器×皮肤）缓存阈值

### 6.2 门禁判定标准（G1–G8，实验步骤见 02 §7）

| # | 前提 | 通过标准 | 不通过怎么办 |
|---|---|---|---|
| G1 | 16:9 归一化后 Hough 检出 21 圆 | 1080p/1440p **≥90%** 帧精确检出 | 手动点 21 点 + 网格吸附 |
| G2 | "按下=变暗"信噪比 | 通道均值差 **≥25 灰阶**、`Δ/std ≥ 2.5` | 双模板匹配 |
| G3 | 捕获后端够快 | 至少一种稳定 **≥55 fps** | 调后端策略；要求无边框窗口 |
| G4 | 时序精度 | onset 误差 **p95 ≤ 40ms** | 提 FPS / 时间戳插值 |
| G5 | 端到端 | 23 首 播→录→识别 **F1 ≥ 0.95** | 调阈值与去抖 |
| G6 | 自身 HUD 不污染采样 | 采样漂移 **< 3 灰阶** | HUD 避让/隐藏；窗口模式 |
| G7 | 数据链路成本 | 单帧 p95 **<8ms**、**零落盘** | 降采样步长 / 只采 ROI |
| G8 | 视频源可用 | 1080p 视频：标定通过且 **F1 ≥ 0.90** | 双模板匹配；文档标注精度预期 |

### 6.3 性能预算（NFR）

| 环节 | 目标 | 备注 |
|---|---|---|
| 取帧 | 0–3 ms | 后端已缓存最新帧 |
| 采样 21 ROI（步长 4） | 0.3–1 ms | numpy 切片 + mean |
| 状态机 | <0.05 ms | 21 次比较 |
| UI 预览摊销 | <0.2 ms | 500ms 一次、降采样 |
| **合计** | **<5 ms/帧** | 60fps 预算 16.7ms，余量 3 倍 |

- CPU ≤15%（4 核）；内存 ≤400MB；启动 ≤3s；连续录制 30 分钟内存增长 <50MB。

## 7. 技术要点

### 7.1 HDR 捕获（j-HDR 后端，M3e 已实现）

根因：HDR 下 DWM 把桌面合成为线性 scRGB FP16，四条常规取帧路（BitBlt/DuplicateOutput/WGC-8bit/PrintWindow）都被截断式转 BGRA8，"键帽变暗"的差值信号消失。正解 = **`DuplicateOutput1` 取 FP16 + 按每屏 SDR 白电平归一 + 高光按最亮通道缩放保色相**，选用现成轮子 **`j-hdrcapture`**（Rust 扩展 `hdrcapture`）：

- SDR 下无损直通（三路 A/B 与 GDI 平均绝对差 0.00）；`grab_region(1600×900)` 3.1ms（GPU 裁剪，别整屏读回）；
- 落地为 `capture/hdr_backend.py`（界面名 **j-HDR**，默认档）：区域必须完整落在单屏内；`AccessLost`/`DimensionsChanged` → 回退链 `hdr→dxgi→gdi`（回退必须说出来）；与 dxgi **互斥**；
- 打包必须 `hiddenimports += hdrcapture`（延迟导入）；剪 dxcam 子模块要 hiddenimports filter **和** `EXCLUDES` 两处同改；
- **切 HDR/后端后必须重学基线**（跨色彩映射的基线不通用）；
- `adaptive=True` 会随内容压暗整屏，与差值判据冲突，**禁用**；库较新，建议 vendored wheel。

### 7.2 键鼠模拟（`inputsim.py`，M3g 已实现）

结论：借鉴 BGI 的抽象（SendInput 前台 + PostMessage 后台双通道），用 Python ctypes 自实现，**不引入 MAA 整个框架**。

- 已实现：`left_click()`（模式 2）/ `press_space()` + `window_at()` + `is_own_window()` + `activate_window()`（模式 1），入口 `main_window._record_click_warmup()`，由 `instruments.json` 全局 int `record_click`（0/1/2）驱动；
- 关键安全阀：激活复核不通过**坚决不发空格**（会落回本程序「录制」按钮误停录制）；命中本进程窗口不发；失败只提示不拦录制；
- 时机特权：用户刚点完「录制谱面」→ 本进程是前台进程 → 命中微软 `SetForegroundWindow` 放行条件，激活大概率一次成功；
- 待扩展：试听驱动游戏键（BGI 模板：`HashSet` 按键去重 + `ReleaseAll` 兜底防卡键）；`settings.json` 可加 `input.backend`（**输入后端与截图后端是正交的两件事**）。

### 7.3 主要风险与缓解

| 风险 | 缓解 |
|---|---|
| HUD 污染采样（屏幕区域模式） | HUD 自动避让 → 隐藏 → 提示切窗口模式（G6） |
| 视频源色度失真 / DRM 全黑 | 单独标定（更保守）+ 双模板匹配兜底；黑帧检测 + 明确提示 |
| 后端在个别机器全不可用 | 4 后端 + 明确报错 + 文档（关"窗口化游戏优化"/改无边框） |
| 音频延迟导致听感不同步 | 高亮由事件时间驱动；提供"音频延迟校准" |
| BGI 键位被用户改过 | 导出说明 + 可选截图校验 |
| 打包误报 | onedir + 不 UPX |

> 团队/进度类风险见 02 §12。
