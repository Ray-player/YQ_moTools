## 2. M3e · HDR 截图后端 j-HDR（2026-10-22，契约 v1.32/v1.33）

**根因**：HDR（或 Win11 24H2 ACM）下 DWM 把桌面合成为**线性 scRGB FP16**（1.0=80nits，SDR 白点≈2.5），而 `DuplicateOutput`/BitBlt/WGC-8bit 三条路都被**截断式**转 BGRA8 → 不是黑屏，是**灰阶塌陷**，"键帽压暗差值"判据直接失效。技术总结已并入 [01 §14](01-设计-产品与技术架构.md)。

**选型**：BGI 的 BitBlt **没有任何 HDR 代码**，它"能用"是靠 `AutoDisableGenshinHdrEnabled`（默认 true）启动时改注册表关掉游戏内 HDR；其 WGC-FP16 shader 用固定 `×0.25` 曝光（官方自认"部分功能仍不可用"）。MAA 至今不做 HDR（PR #1105/#1300 均未合并）。最终选 **`j-hdrcapture`**（`DuplicateOutput1` 取 FP16 + 逐屏真白点归一 + 高光按最亮通道缩放保色相）——SDR 下与 GDI **逐像素一致**（三路 A/B 平均绝对差 0.00），`grab_region(1600×900)` 3.1ms。

**落地**：
- 新增 `capture/hdr_backend.py`：内部名 `hdr`、界面 **`j-HDR`**；全局物理坐标 `grab_region`（GPU 裁剪后只读回区域）；区域必须完整落在单屏内（跨屏 `ValueError`）；`InitialFrameTimeout`→`None`（只计丢帧）、`AccessLost`/`DimensionsChanged`→`RuntimeError`（触发回退/重建）；与 dxgi **互斥**（DXGI 同一输出只允许一个 duplication 会话）。
- 回退链 `FALLBACK_CHAINS`：`hdr→(hdr,dxgi,gdi)`、`dxgi→(dxgi,gdi)`、`gdi→(gdi)`；回退必须"说出来"（红字 + 状态栏徽标「回退」）。
- 默认后端 `dxgi`→**`hdr`**（`CONFIG_VERSION 3→4` 迁移旧档）；用户选择写 `settings.json` 记住；**标定档的 `backend` 只作记录不再覆盖 UI**。
- 打包：`hiddenimports` 加 `hdrcapture`（延迟导入，静态分析看不到）；剪 dxcam 的 `winrt` 必须 **hiddenimports filter 与 EXCLUDES 两处同改**（静态分析会顺着函数级 import 捞回来）；`build_release.py` 加 `_cleanup_stage()` 修掉 `%TEMP%` 每轮遗留 ~200MB（累计 1.2GB）。

**遗留**：本机两块屏都不支持 HDR，HDR 真实效果**待实机**（有 HDR 屏跑 `tools/hdr_probe/probe_hdr_ab.py`）；`j-hdrcapture` v0.1.0 太新，建议后续 vendored wheel；切 HDR/后端后**必须重学基线**。

## 3. M3f · 首次运行关闭按钮置灰 + frozen 日志坑（2026-10-22，契约 v1.34）

**现象**：打包 exe 首次运行标题栏 X 有时禁用（无 C 盘存档更易现）。

**定位**：全代码无关闭按钮控制逻辑 → 唯一会把 X 置灰的机制是 **Windows ghost 窗口**（窗口可见后主线程停摆 >5s）。锁定唯一一处"首次运行 + post-show + 主线程写盘"链路：`_restore_window_size` 置 `_ui_ready` → setGeometry → move/resize 400ms 防抖 → mkdir + 新建 settings.json（杀软扫描可卡数秒）。

**修法**：`MainWindow.__init__` 末尾 `if not config_path().exists(): self._save_app_config()`——**pre-show 建档**，把唯一的首次运行写盘挪到窗口可见之前。Win32 探针 `out/probe_close_button.py`（IsHungAppWindow + GWL_STYLE + SC_CLOSE 菜单项态）可发报告者机器复跑。

**排查中的重大发现**：打包版**文件日志从未装上过**（真实机数据目录无 `logs/` 即铁证）——`app.py` 在 frozen 下以 `__main__` 运行，里面禁止相对导入（`from .config import …` ImportError 被 `run_gui` 的 except 静默吞掉）。改绝对导入 + 失败留档 `%TEMP%\yqrec_log_fail.txt`；`cli.main()` 对 `gui` 子命令跳过无目录的 `setup_logging()`（否则 `_configured` 置位后文件 handler 永远装不上）。

## 4. M3g · 键鼠输入注入 record_click（2026-10-22，调研 → 落地）

**调研**：源码级研究了 BetterGI（`Core/Input` 三层：InputHub → IInputBackend → IInputChannel，前台 SendInput + 后台 PostMessage 双通道）与 MaaFramework（Win32 输入 10+ 种方式矩阵：Seize/WithCursorPos/WithWindowPos/Interception 驱动级/锚点触摸，两个黑科技 MouseLockFollow 与 BackgroundManagedKeys）。技术总结已并入 [01 §15](01-设计-产品与技术架构.md)。

**落地**（借鉴 BGI 前台通道 + MAA `ForegroundUtils.h` 三段式）：

`assets/instruments.json` 顶层 **`record_click`（int，全局，所有乐器一致）**：

| 值 | 行为 |
|---|---|
| `0` | 不启用（代码缺省） |
| `1` | **激活窗口+键盘模拟**：`WindowFromPoint(区域中心)→GA_ROOT` 找窗口 → 排除本程序窗口 → MAA 三段式激活（`HWND_TOP` 提层 → `SetForegroundWindow` → `GetForegroundWindow` 复核，失败 TOPMOST↔NOTOPMOST 强提再复核）→ SendInput 空格 down/up 60ms |
| `2` | **鼠标点击模拟**：区域中心左键点击 + 恢复光标原位（MAA WithCursorPos 思路） |

- **安全阀**（模式 1 最大风险）：激活复核不通过**坚决不发空格**——空格会落回本程序焦点控件（「录制谱面」按钮）导致录制立即被误停；命中自己窗口同样不发。任何失败只记日志 + 状态栏提示，**绝不拦录制**；注入发生在 `worker.start_recording()` **之前**，不会进谱面。
- 旧写法 `{"enabled": bool}` 兼容读取（→ 2/0），记 info 提示迁移。
- 新增 `inputsim.py`（前台 SendInput 封装：`left_click`/`press_space`/`window_at`/`is_own_window`/`activate_window`），后续试听驱动游戏键在此扩展。
- 兼容性要点：用户刚点完「录制」按钮 = 本进程是前台进程且收到最后输入事件 → 命中微软 `SetForegroundWindow` 放行条件，激活大概率一次成功（这是该方案的时机特权）。
- 测试：解析容错 8 条 + UI 门控 2 条（替身验证：激活成功发空格 / 失败不发 / 命中自己不发）；发布 JSON 断言只锁"显式配置了合法 int"（0/1/2 都是合法运行态，不锁死具体值）。
