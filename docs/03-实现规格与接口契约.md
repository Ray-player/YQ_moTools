## 0.2 数据模型与不变式（`src/yqrec/types.py`）

```python
Rect(left, top, width, height)                    # right/bottom 为派生属性
ScreenTarget(monitor, rect)                       # 屏幕物理像素，虚拟桌面绝对坐标
WindowTarget(hwnd, norm=(u0,v0,u1,v1))            # 客户端归一化
CaptureTarget = ScreenTarget | WindowTarget
CaptureStats(fps, dropped, last_error=None)

KeyThreshold(min_r, max_r, min_g, max_g, min_b, max_b,
             mode="channel", delta=0)             # mode: channel|max_drop|chroma|euclid|weighted
KeyArea(code, name, channels, keys)
KeyPoint(u, v, r)                                 # 归一化；r 按 1920 宽归一化
KeyGrid(points, key_count)
InstrumentSpec(id, name, key_count, sustain, areas,
               note_to_key, note_to_audio, default_thresholds, hough)
SamplingSpec(ring_width_ratio, square_side_ratio, ring_points, square_points, point_patch_ratio)

RgbSample(ts, rgb)                                # rgb: (K,3)
PressEvent(key, down, ts)
NoteEvent(keys, onset_ms, sustain_ms=0.0)
RestEvent(ms)
ScoreEvent = NoteEvent | RestEvent
Diagnostic(message, offset, length, level)        # level: error|warning
```

**不变式（构造时校验）**

1. `NoteEvent.keys` 非空、无重复、均为 `note_to_key` 的值集；
2. `onset_ms` 单调不减；`sustain_ms >= 0`；
3. `KeyGrid.points` 长度 == `InstrumentSpec.key_count`；
4. 归一化坐标 `u, v ∈ [0,1]`，`KeyPoint.r` 是**比值**（除以 1920）不是像素。

全部 dataclass 用 `frozen=True`；`slots=True` 时默认值必须引用模块级 `DEFAULT_*` 常量、`to_dict` 用 `dataclasses.asdict`。

## 0.3 跨模块红线（改代码前后都要对一遍）

| # | 红线 | 违反后果 |
|---|---|---|
| 1 | 新增判据 metric 必须**三处同改**：`KeyThreshold.accepts()` / `PressDetector._signals()` / `keys_panel.update_samples()` | 漏 `_signals` → 调 Δ 不亮；漏 `accepts` → 校验与实测不一致 |
| 2 | 改采样几何（半径/环宽/边长/点数）或切后端/HDR 后**必须重新学习基线** | 基线口径不符 → 常按或全不亮 |
| 3 | 改 `confirm_frames` / `delta` 后必须 `worker.set_spec()` 重建判按器 | 界面参数变了、后台仍用旧值 |
| 4 | 判按事件时间戳取**首帧**（`st.pending_since`），不是确认帧 | 整体时序偏移 N 帧 |
| 5 | 谱面「录制内容」文本框是**唯一来源**；程序写入必须 `blockSignals` | 触发 `textChanged` 重解析/停播死循环 |
| 6 | tick 中**任何两个不同 onset 之间必须有 Rest（≥1ms）** | 连写被解析器合并成一个和弦 |
| 7 | 和弦内键拼接顺序 = `note_to_key` 顺序（`+1..+7, 1..7, -1..-7`） | 与既有 tick 工具链/高亮错位 |
| 8 | 延音 `<50ms` 不写 `[ms]` 后缀 | 噪声被当成延音 |
| 9 | BGI `midi` 的 token 数字是「**本事件之前**的等待 tick」的**增量** | 整曲节奏错位 |
| 10 | `yuanqin` 是单声部顺序播放：**叠音 / 超长延音一律导 `midi`** | 延音被截断（UI 需 warn） |
| 11 | `settings.json` 的 `backend` 是截图方式**唯一真相**；标定档 `backend` 只作记录 | 每次启动被拽回旧后端 |
| 12 | 颜色只从 `ui/theme.py` 令牌取；QSS/绘制里出现硬编码 `#hex` 即 bug | 主题切换失效 |
| 13 | `objectName` 是 QSS 唯一挂钩点，改名即掉样式；`setProperty` 后必须 `theme.repolish()` | 状态样式不刷新 |
| 14 | 所有落盘路径走 `config.data_dir()`，**绝不退回 cwd** | 文件写进 exe 目录（权限/便携双坑） |

## 0.4 三个配置文件的分工（不要混）

| 文件 | 位置 | 内容 | 谁写 | 何时读写 |
|---|---|---|---|---|
| `settings.json` | `<data_dir>\` | 本机 UI 状态：窗口几何/置顶/后端/检测方式/乐器/音量/录制参数 | 程序 | 启动读**一次**，操作时防抖写 |
| `profiles/default.json` | `<data_dir>\profiles\` | 标定结果：框选区域、键位、**逐键基线**、阈值 | 程序 | 启动读一次，标定后写 |
| `assets/instruments.json` | 程序目录（打包后 `_internal/assets`） | **识别参数**：乐器、Δ、判据、参考色、采样几何、音频映射、`record_click`、`archive_path` | 人（半径滑条也写 `sampling`） | 启动读一次 + 按需重读 |

`<data_dir>` 解析（`config.data_dir()`）：`YQREC_DATA_DIR` 环境变量 → `instruments.json` 的 `archive_path` → 默认 `%APPDATA%\YQ_moTools`（`APPDATA` 拿不到退注册表 `User Shell Folders\AppData`，再退主目录）；全失败抛错。**绝不使用相对路径/回退 cwd。**

## 0.5 后端回退链

| 用户选择 | 顺序 |
|---|---|
| `j-HDR` | `hdr → dxgi → gdi` |
| `dxgi` | `dxgi → gdi`（**不会**偷偷用 hdr） |
| `gdi` | `gdi` |

`default_backends()` = `[hdr, dxgi, wgc, gdi, printwindow, file]`（CLI `--backend auto` 走这条）。
**回退必须说出来**：`CaptureManager.start_errors` 逐项记录失败原因 → `CaptureWorker.backend_fallback` 信号 → 界面红字 + 状态栏后端名后缀「（回退）」。

## 0.6 线程边界

| 线程 | 拥有者 | 允许操作 |
|---|---|---|
| 捕获线程（库内部） | 库 | 只产帧 |
| 分析线程 | `CaptureWorker` | 读最新帧 → 采样 → 判按 → 推 `RecordingBuffer`；**唯一写 samples** |
| UI 线程 | Qt | 只读快照（预览帧/统计/事件），不得直接调捕获 |
| 音频线程 | pygame | 只播声音；回调经 Qt Signal 回主线程 |

跨线程传「最新预览帧」用 `queue.Queue(maxsize=1)` 覆盖式写入（`get_nowait` 清空旧值）。

## 0.7 错误码

| 码 | 场景 | 处理 |
|---|---|---|
| `E_CAPTURE_OPEN` | 后端打不开（权限/驱动/窗口消失） | 提示换后端/改窗口模式 |
| `E_CAPTURE_BLACK` | 连续 20 帧全黑 | 提示 DRM / 独占全屏 / 关「窗口化优化」 |
| `E_KEYGRID_MISMATCH` | Hough 圆数 ≠ `key_count` | 自动转手动点选 |
| `E_CALIB_LOW_SNR` | 某键 `Δ/std < 2.5` | 标红该键，提示换角度/关滤镜 |
| `E_PARSE` | 谱面语法错误 | 编辑器按 `offset` 定位并波浪下划线 |
| `E_EXPORT` | 导出失败（权限/路径） | 提示路径 |
| `W_TOKEN_MERGE` | 两和弦无 rest（会被合并） | 自动补 1ms rest + 提示 |
| `W_SUSTAIN_DROPPED` | 延音在导出格式中无法完整表达 | 导出前确认对话框 |

## 2. 捕获（`capture/`）

### 2.1 坐标映射

```python
def target_to_frame_rect(target, frame_w, frame_h, *, win_client=None) -> Rect:
    if isinstance(target, WindowTarget):
        u0, v0, u1, v1 = target.norm
        return Rect(round(u0*frame_w), round(v0*frame_h),
                    round((u1-u0)*frame_w), round((v1-v0)*frame_h))
    return Rect(0, 0, frame_w, frame_h)   # ScreenTarget：后端已裁剪，整帧即目标
```

- `ScreenTarget` + DXGI/GDI：`open()` 时把 `rect` 传 `region=`，之后整帧即目标；
- `WindowTarget` + WGC：整窗帧 + 上述归一化裁剪；
- `WindowTarget` + DXGI/GDI：`GetClientRect` + `ClientToScreen` 转屏幕矩形当 `ScreenTarget` 用（窗口移动时每 500ms 或 `EVENT_OBJECT_LOCATIONCHANGE` 刷新）。

### 2.4 j-HDR（`hdr_backend.py::HdrBackend`）

| 项 | 实现 |
|---|---|
| 会话 | `hdrcapture.Capture(timeout_ms=16)` 常驻；**同一输出只允许一个 duplication 会话**，与 dxcam 互斥（切换先 close） |
| 区域 | `grab_region(l,t,w,h)` 用全局物理坐标；`pick_monitor()` 要求区域**完整落在单块屏**内，跨屏拒绝并回退 |

| 首帧 | `InitialFrameTimeout` → 返回 `None`（计丢帧，不逼降级）；`AccessLost`/`DimensionsChanged` → `RuntimeError`（让管理器回退/重建） |

### 2.5 取帧与分析节奏（`ui/capture_worker.py`）

| 环节 | 现状 |
|---|---|
| 抓帧 | `target_fps=0`（**不 pacing**；DXGI 复制本身已被桌面 present 限速） |
| 分析 | 每拿到一帧就采样 + 判按，无条件执行 |
| 预览 | 每 3 帧转一次 `QImage`（`PREVIEW_EVERY=3`） |
| 键位面板 | 每 3 帧发一次 RGB 快照（`SAMPLES_EVERY`） |

状态栏文案：`后端 | FPS: 处理帧率 | 源: xx.xfps(间隔ms) | 单帧 | 帧数`。
`源` 来自后端帧时间戳中位间隔 —— 只有「源 60 但 FPS 30」才是程序侧丢帧；两者都低说明游戏本身帧率低。

## 3. 键位检测（`vision/keygrid.py`）

### 3.1 找圆（Hough）

```python
def detect_keys(frame, hough, key_count) -> list[Circle]:
    h, w = frame.shape[:2]; s = w / 1920.0
    y0 = int(h / 3)                                   # 只取下面 2/3
    gray = cv2.cvtColor(frame[y0:, :], cv2.COLOR_BGR2GRAY)
    mask = cv2.inRange(gray, 0, int(hough["upper_bound"]))     # 挖掉高光 → 只剩暗环
    circles = cv2.HoughCircles(mask, cv2.HOUGH_GRADIENT, dp=hough["dp"],
        minDist=hough["min_dist"]*s, param1=hough["param1"], param2=hough["param2"],
        minRadius=int(hough["min_radius"]*s), maxRadius=int(hough["max_radius"]*s))
    return [Circle(x, y + y0, r) for x, y, r in (circles[0] if circles is not None else [])]
```

参数（1920 宽基准）：`dp=2.0, minDist=80, param1=20, param2=40, minRadius=40, maxRadius=53, upper_bound=239`。
`param1/param2` 与 OpenCV 常见默认**相反**，以 20/40 为准。

### 3.2 网格校正（`correct_button_coordinates`）

```
输入 circles：长度必须是 7 的倍数且 >= 14，否则原样返回
1. 按 Y 升序排序
2. 切 rows = len//7 段，每段 7 个，段内按 X 升序
3. row_y[i] = 第 i 段 7 个圆的 Y 均值；col_x[j] = 所有段第 j 个圆的 X 均值
4. 每圆 center = (col_x[j], row_y[i])，半径保留
5. 输出：**倒序遍历段**（Y 最大段先输出），段内按 X 升序
```

输出第一行 = 画面最下面那排，`circle_map_note` 依赖该顺序，**不要重复排序**。

### 3.3 圆 → 音名（`circle_map_note`）

```
1. len(circles) != key_count → ValueError（上层转手动点选）
2. 按 (Y, X) 排序 → 行主序
3. key_count % 7 == 0 时每 7 个一段、段内按 X 排序后拼接
4. 依 note_to_key 的键顺序（+1..+7, 1..7, -1..-7）逐项配对
→ 最上排 = +1..+7（高音），中排 = 1..7，下排 = -1..-7
```

### 3.4 手动点选兜底

用户依次点 21 个点 → 同样走网格校正（或 7×3 均值吸附）→ 归一化 `u,v` 与 `r/W` 得到 `KeyGrid`。

## 4. 取色（`vision/sampler.py` / `vision/pointsampler.py`）

### 4.1 三种口径

| 口径 | 类 | 几何来源 | 说明 |
|---|---|---|---|
| 环形均值 | `KeySampler(inner_ratio>0)` | `sampling.ring_width_ratio` → 内径 `0.98−width`，外径固定 `0.98R` | 掩膜只统计环带 |
| 方块均值 | `KeySampler(inner_ratio=0, square_side=…)` | `sampling.square_side_ratio` | 半边长 `r·square_side/2`，恒居中 |
| **分段点（界面默认）** | `KeyPointSampler` | `ring_points` / `square_points` / `point_patch_ratio` | 沿圆周或四边取固定基准点；`MainWindow` 一律传 `point_sampling=True` |

`CaptureWorker._ensure_sampler()` 按 `point_sampling` 开关二选一，两种类接口一致；CLI/`Session` 仍走 `KeySampler`。

```python
def sample_key(frame, cx, cy, r) -> tuple[int, int, int]:
    x0, y0 = max(0, int(cx - r)), max(0, int(cy - r))
    w = min(int(r * 2), frame.shape[1] - x0); h = min(int(r * 2), frame.shape[0] - y0)
    if w <= 0 or h <= 0: return (0, 0, 0)
    b, g, r_ = frame[y0:y0+h, x0:x0+w].reshape(-1, 3).mean(axis=0)   # BGR
    return (int(round(r_)), int(round(g)), int(round(b)))            # 返回 RGB
```

**性能要求**：不要逐键临时切数组，预计算每键切片并按 `stride=4` 降采样；环形掩膜同样按 `np.arange(y0,y1,stride)` 预计算，尺寸必须与 ROI 严格一致；掩膜为空时退回整块均值。半径取 `button_radius`（归一化 ×1920），**不是** Hough 输出半径。

### 4.2 分段点采样

| 模式 | 基准点位置 | 起点 | 点数 | 默认半径 |
|---|---|---|---|---|
| 环形 | 内环圆周（半径 `ring_inner_ratio·R`） | 内环**正上方**切点 | `sampling.ring_points`（默认 8） | `0.80R` |
| 方块 | 四条边（边长 `square_side_ratio·R`，恒居中） | 左上角，顺时针 | `4 × square_points`（默认 16） | `0.55R`（半边长） |

每点取周围 `point_patch_ratio·R`（默认 0.06R，≥1px）圆斑均值，再对本键所有点求均值 → 每键一个 RGB。
越界点直接裁掉（不 clamp）；整键无有效点返回 `(0,0,0)`；帧尺寸变化要重建。

### 4.3 纵向偏移

`offset_y` 单位是 **1920 宽基准像素**，实际帧缩放：`dy = offset_y * frame_w / 1920`。`_bounds()` 与 `_make_mask()` 都做 `cy += dy`，保证取值窗口与掩膜同位置。仅小方块模式生效（`_effective_offset_y()` 在环形返回 0）。测试换算：400 宽帧上想移 40px，传 `40 * 1920 // 400 = 192`。

### 4.4 采样可视化（`ui/preview.py`）

- 检测圈画出即带**常显小红点**（`POINT_DOT_COLOR`，半径 `max(1.8, 0.09R)`），位置用 `base_points()` 与采样同源函数；
- 圈的绘制按 `MARKER_SCALE=1.6` 放大（只为看清边界），点半径用真实 `KeyPoint.r`；
- `show_sample_overlay(grid, inner_ratio=…, offset_y=…)` / `clear_sample_overlay()`：环形用 `QPainterPath` + `OddEvenFill`（外圈减内圈），方块直接 `fillRect`，颜色 `SAMPLE_FILL/SAMPLE_STROKE`；
- 生命周期严格挂在基线上：`_learn_baseline()` 显示 → `_on_baseline()`（唯一出口，含超时/失败）清除；
- `set_sampling(show_points=False)` 可整体关掉红点（测试/截图）；
- 按下绿圈：填充 alpha 42（`PRESSED_FILL_ALPHA`）、描边 190、线宽 1.8。

## 5. 判按（`timeline/detector.py`）

### 5.1 判据分派

`KeyThreshold.accepts()` 与 `PressDetector._signals()` **两处都必须分派**（前者供校验/测试，后者供实时判定），否则新 metric 会掉进「单通道区间」分支而被跳过。

| `mode` | 标量值 | 判按下 |
|---|---|---|
| `max_drop` | `max(base_c − cur_c)` | `>= Δ` |
| `chroma` | `(cur_to − cur_from) − (base_to − base_from)` | `>= Δ` |
| `euclid` | `‖cur − base‖ / √n` | `>= Δ` |
| `weighted` | `Σ w_c·max(0, (base_c−cur_c) − tolerance) / Σ w_c` | `>= Δ` |
| `channel`（旧） | 各通道值 | 全部落进 `[min, max]` |

- `chroma` 方向 `(from→to)` 由 `unpressed_ref`/`pressed_ref` 自动推出；
- `weighted` 只算变暗方向；`w_c` 取 `detection.weights`，缺省由 refs 跌幅归一化（`w ∝ max(0, unpressed−pressed)`），两者都缺则等权；`tolerance` 默认 8；
- 通道选择用 `KeyArea.channels`，为空时退化为「任一通道阈值 > 0」。

### 5.2 状态机与 `confirm_frames`

```
每键独立状态机（毫秒域）：
  enter[i] = min_th
  exit[i]  = min_th + hysteresis * (max_th − min_th)
  未按下且 v <= enter → 候选（seen=1，记 pending_since=本帧 ts）
  候选持续到 seen >= confirm_frames → 发 down(ts=pending_since)
  已按下且 v > exit → 发 up
```

- `confirm_frames` 在**乐器**里：`detection.confirm_frames`（1~10，默认 1；发布 JSON 多写 2）；计数是**连续**的，一帧不满足即归零；越界回落 1 并 warning；
- `settings.record.min_hold_ms` 降级为「绝对时长下限」，默认 0，一般不动；
- `min_gap_ms`：同键两次按下最小间隔。间隔不够时把 `pending_since` 推到当前帧重数（`seen=1`），够 30ms 再补认 —— **不再整段丢弃**；
- `short_presses` 统计「刚好用满 `confirm_frames` 就确认」的次数，停录时写日志（该值大 = 轻按多/帧率低）；
- `update/flush` 持 `_judge_lock`。

### 5.3 逐键基线

`PressDetector(spec, thresholds, baseline=(K,3))` 用逐键基线替换阈值里的 `base_*`；配置档 `baseline` 段保存它，旧档缺该段则退回区域均值。`keys_panel` 的实时数值走同一套逐键阈值，保证「看到的数 = 判定用的数」。
`_suspicious_baseline_keys()` 必须**按 area 分组**统计（双区乐器一次算全 21 键会误报）。

### 5.4 事件装配（`timeline/assembler.py`）

```python
def assemble(presses, *, chord_window_ms=25, guard_ratio=None, key_count) -> list[ScoreEvent]:
    """
    1. up 按 key 与对应 down 配对 → (key, down_ts, hold_ms)
    2. 按 down_ts 排序；相邻差 <= chord_window_ms 合并为同一和弦
    3. 和弦 sustain_ms：乐器 sustain_ms==0 → 0；否则取「hold >= sustain_ms」者里最大的
       hold（值为完整按住时长，不足阈值一律 0）；无 per-key 延音
    4. rest_i = onset_{i+1} − onset_i；末和弦后不加 rest
    5. 场景保护：同刻按下键数 >= key_count − 5 → 整体丢弃 + warning
    6. rest_i < 1ms 且两和弦不同 → 强制 1ms
    """
```

```python
tick_spans(text) -> list[tuple[int, int]]            # 试听高亮用
```

**tick 文本规则（写入端）**

- 字母 = 和弦（同刻按键连写）；`[ms]` = 延音后缀（**≥50ms 才写**）；数字 = 与上一个和弦**按下**之间的毫秒间隔；
- 间隔基准是上一个和弦的「按下」而非「抬起」，`[ms]` 不推进时间轴：`A[800]1000F` → A 在 0 按下、800 抬起、F 在 1000；
- 延音时长于间隔即叠音（`A[1200]300F` 合法），不推后后续音；
- 间隔用「累计已输出毫秒」差分算 `gap_ms`，整首误差 ≤0.5ms，与帧率无关。

**解析容错**：允许字母与 `[` 之间有空格；方括号内非正整数 → 延音按 0 但整段吃掉；没有闭合 `]` → 不当延音也不吞后续内容。
`tick_text()` 只吃 `RecordedNote`（`TickNote` 是另一个类），`tick_text(parse_tick_text(t))` 会 `AttributeError`；需要往返请走 Score 通道（`score_from_tick_text` / `tick_text_from_score`）。

**收尾顺序**：`stop_recording` 先 `close()`，再 `flush(最后一帧 ts)`，最后 `finish(extra=…)`。

## 7. 格式：tick（`formats/tick.py`）

### 7.1 语法

```ebnf
document = { blank | comment | rest | chord | unknown } ;
comment  = "/*" { any } "*/" | "//" { any } "\n" ;   (* 体内每行可含 "@key value" *)
rest     = digit+ ;
chord    = note-char { [ "." duration-digits ] note-char } ;
unknown  = 其它字符（记 warning，跳过） ;
```

**解析语义**

```
Comment → 若尚未出现任何 Rest/Chord，按行匹配 ^@(?<key>[A-Za-z][\w-]*)\s+(?<value>.+)$ 收集元数据
Rest    → RestEvent(ticks=int(token))；非法数字 → error 诊断
Chord   → 逐字符：字母入 keys；后随 "." 则读 [0-9.]* 作为该音符延音，取「比当前更大」的最大值
Blank   → 跳过
```

元数据只在首个 Chord/Rest **之前**生效（`@name` 必须放文件头）。

### 7.2 序列化

```
NoteEvent：sustain_ms >= 50 → 每键写 "X.<sustain>"，键之间空格分隔（`A.500 S.500`）
           否则 → 所有键直接连写（"AS"）
RestEvent：输出整数毫秒
事件之间用空格分隔
```

生成端两条硬规则：不同 onset 之间必须有 Rest（≥1ms）；和弦键序 = `note_to_key` 顺序。
推荐输出骨架：

```
/*
  @name <曲名>
  @instrument 风物之诗
*/
DBZ.731 731 MXB.731 731
```

### 7.3 只读格式

| 格式 | 要点 |
|---|---|
| `fengwu` | 头部 `t = <float>`（缺省 0.22 + warning）；连续空格 = Rest，但空格后紧跟 `/`/换行/文件尾视为 Blank；`/` 小节线不产生事件；`(...)` 为和弦；每 Rest 计 166 ticks |
| `domiso`（含 `.dms`） | 头部 `bpm`（默认 80）、`1 = <A-G><oct?><#\|b>`（默认 C4=60）；音符正则 `^(~)?(-*\|\+*)([0-7])(#\|b)?((/\|-\|\.)*)$`；音高 = `BaseMidi + BaseOffset[note] + scale*12 ± 1`，`BaseOffset=[0,0,2,4,5,7,9,11]`；时值以 `60000/bpm` 为基拍，`/` 减半、`-` 加拍、`.` 附点；`()` 同 onset、`{}` 连音、`~` 琶音（每音延迟 40ms）；`rollback` 回退时间轴 |

容错策略统一：无法识别的 token 记 warning，不中断整曲。

> 这两个格式**当前仍是占位**：`formats/fengwu.py` / `formats/domiso.py` 的 `parse()` 直接 `raise NotImplementedYet`（P2 实现），上表是解析规格。

## 8. 格式：BetterGI（`formats/bgi_sheet.py`）

### 8.1 格式事实

`type` 三种：`midi`（纯时间事件流）、`yuanqin`（音符时值记号）、`keyboard`（**不支持**）。
本项目支持 `midi` 与 `yuanqin`。

**`midi`** 结构：`{"name","author","instrument","bpm","ticks","type":"midi","notes":"DZ338|DE39|..."}`
token：`^([DU])([A-Z@]+)(\d+)$` —— `D`/`U` = 按下/抬起，中间为游戏键名（多字母 = 和弦，`@` = 空拍），末尾 = **本事件之前**先等待的 tick 数（`play_sheet` 先 `await playbackSleep(wait)` 再按键）。`*120` 为 BPM 变速标记，需改 `base_time`。
时间基准 `ms_per_tick = 60000/(bpm*ticks)`；本项目导出用 `bpm=125, ticks=480` → **1 tick = 1ms**。

**`yuanqin`** 记号：`A[8]` 单音、`(ASD)[4]` 和弦、`@[2]` 休止、`%[72]` 变速、`[4-*]` 附点、`[16-#]` 装饰音、`[4-8.3]`/`[4-8.$]` 连音；`|` 分段。
时值：`symbol_time = round(60000/bpm)`（JS `Math.round` 语义），`dur = round(symbol_time × symbol/type)`，`symbol` 取拍号分母，附点 ×1.5，装饰音 `round(symbol_time/16)` 并从前一音扣。
播放模型：每个 token 是「按下 → 按够时值 → 抬起」的**阻塞序列**，跨 token 不能叠音。

### 8.2 导出：`Score` → BGI

**通用**

1. 每 `NoteEvent` 的每键 → `down`(onset) + `up`(onset + hold)；
2. `hold`：`sustain_ms>0` 用它，否则 `DEFAULT_HOLD_MS=60ms`；只按**同一个键**的下次按下裁剪（留 `MIN_REPRESS_GAP_MS=30ms`）；不同键允许重叠（BGI 是事件流，可表达多声部）；
3. 排序 `(time, down 先于 up, key)` 稳定排序；同 tick 同状态的键合成一个 token，键按 `key_order` 排；
4. tick 化用**绝对位置差分**（`tick_i - tick_{i-1}`，≥0），避免累计漂移；首 token 数字 = `tick_0`；
5. 元数据 `type`、`ticks=480`、`bpm`、`instrument`（BGI 显示名：`fwzs→风物之诗琴`、`jhzq→镜花之琴`、`ljdsq→老旧的诗琴`、`ykq→悠可琴`、`yy→余音`），`name` 默认取文件名（BGI 要求与文件名一致）；
6. 不产生 `@` token（节奏全部由「事件前等待」表达）。

**`midi` 特化**（1 tick = 1ms）：`onset_ms` 直接四舍五入成 tick；示例 `DA0|UA60|DDF440|UDF60`。数字是增量，校验须逐 token 累加。

**`yuanqin` 特化**（`bpm=300`，一拍 200ms；档位 `[1][1-*][2][2-*][4][4-*][8][8-*][16][16-*][32][48][64]` = 800/1200/400/600/200/300/100/150/50/75/25/17/13ms）：

1. 每音占 `min(到下一音的间隔, 上限)`；上限：不延音乐器 `YQ_MAX_HOLD_MS=100ms`，延音乐器 `YQ_MAX_HOLD_MS_SUSTAIN=4000ms`；取**不超过它**的最大档，用 `_yq_nearest_ms()` **就近**取档；
2. 剩余空档用 `@[n]` 补齐，休止可拆多个 token；
3. 时间轴按**绝对时刻 + 解析端会算出的毫秒**累加推进；
4. 相邻两音有共同键时音符时值再减 30ms，强制中间多一个 `@`（BGI 会对 `hasCommonChar` 提前抬键）；
5. 每满 4 拍补一个 `|`（纯可读性）；
6. 乐器没有的键直接丢弃（该 token 降级成 `@`），时间轴不变。

`upper` 硬边界 = 下一音起点（同键再留 30ms）。`yuanqin_sustain_loss(score, spec) -> SustainLoss(count, max_ms)` 统计被截短处，UI 保存成功后用 warn 提示「要完整延音请改存 BGI · midi」。

### 8.3 导入：BGI → `Score`

**`midi`**

1. 只接受 `midi` / `yuanqin`，其余抛 `BgiSheetError`；
2. 逐 token `cursor += n * ms_per_tick`（先等后按），登记 `down`/`up` 时刻并配对；
3. 同一时刻（±5ms）按下的键合成一个 `NoteEvent`，`sustain_ms` = 和弦内最大保持；
4. `*120` 变速标记后重算 `ms_per_tick`；
5. 非法 token 跳过 + warning；
6. `name/instrument/author` 进 `metadata`，`instrument` 反查回本地乐器 id。

**`yuanqin`**：连续音符按 `dur` 累加得 onset，`sustain_ms = dur`；`|` 不产生时间。

### 8.4 已知限制

- `keyboard` 类型不支持；
- `yuanqin` 连音（`.3/.6/.$`）按「组总时长均分」近似，装饰音从前一音扣（待真实样本校准）；
- BGI 曲谱里本乐器没有的键：解析照收（播放端忽略），导出只用 `key_order` 内的键；
- 读取 BGI 后文本框显示「onset → 60fps 帧号」的等价 tick 文本，仅供人看；试听用解析出的毫秒时间轴。

### 8.5 BGI JS 包（`formats/bgi_js.py`）

```
out_dir/
├─ manifest.json   # manifest_version/name/version/bgi_version/description/authors
│                  # settings_ui:"settings.json" / main:"main.js" / saved_files:[]
├─ settings.json   # {"countdown_ms": 3000}
├─ sheet.json      # {"version":1,"name","instrument","keys":[…],
│                  #  "events":[{"t":0.0,"key":"A","down":true}, …]}
└─ main.js
```

事件生成：每 note 产生 `(t, key, down=True)` 与 `(t + max(hold,50), key, down=False)`，按 `t` 稳定排序（同 t 先 down 后 up）。

### 9.6 按键演奏（M6，`player/keys.py` + `inputsim` 键注入）

**为什么另起一个 Player 而不是给 `Player` 加分支**：`Player` 的事件粒度是"一个和弦响一次"，
而按键演奏要**按下/抬起两个时刻**（延音、重按、卡键都取决于 up 什么时候发）。
`KeyPlayer` 保持与 `Player` 完全相同的接口，所以控制器的进度/暂停/拖动逻辑一行不用改。

| 环节 | 做法 |
|---|---|
| 时间轴 | `build_key_timeline(score)`：每个和弦的每个键 → down/up 一对；按住 = `max(sustain, 60ms)` |
| 交叠 | 同键相邻两段真交叠时前段提前 `30ms` 抬起；"刚好相接"不砍（否则延音白丢 30ms） |
| 同刻次序 | 稳定排序 + `down` 当次序键（抬起在前） |
| 中途起播 | `_held_at(start, strict=True)` 补按仍在延音中的键 |
| 暂停 | `release_all()` + 时间轴冻结；恢复补按 `_last_at_ms` 的按住键 |
| 收尾 | `release_all()` + `force_release(keys_used())`（漏一个 up 就是琴键卡死，多余无害） |
| 焦点守卫 | 每个动作前 `sink.ready()`；`interrupt_when_blocked=True`（后台）→ `on_interrupt` 中断；`False`（前台）→ `on_blocked(True)` **只提示不中断**，这一拍不发键、时间轴照走（M6d） |

**注入通道（`inputsim`）**：

| 通道 | 实现 | 适用 / 风险 |
|---|---|---|
| `ForegroundKeys(hwnd)` | `SendInput` + **扫描码**（`KEYEVENTF_SCANCODE`），打给**当前激活窗口**；`ready()` = 有前台窗口且**不是本进程** | 游戏类 DirectInput/RawInput 只认扫描码。当前激活是本程序时**这一拍不发键**（否则字母会进谱面文本框），但**不暂停**；当时没送出去的 up 记进 `_pending_up`，切回后由 `key_down` 先 `_flush_pending_up()` 补发（防琴键卡死） |
| `BackgroundKeys(hwnd)` | `PostMessage(WM_KEYDOWN/UP)`，lParam 与 BGI `MakeKeyLParam` 同构（重复 1 + 扫描码 + 抬起 `bit30\|bit31`）；目标不在前台时先补 `WM_ACTIVATE` | 不抢焦点、可后台跑；只对读窗口消息的程序有效，RawInput 游戏可能没反应。目标窗口没了**只能中断**（没地方投递） |

**主窗侧**：

- 入口 `_btn_play_keys`（「演奏」）在「试听」**左侧**，两者共用同一条 `_play_bar`；
- **通道胶囊只在演奏控制条里**（v1.49）：入口处那个预选胶囊（v1.46 的
  `_btn_key_mode_entry`）按用户要求**删掉了**。`_btn_key_mode` 是 `checkable`，
  `checked` 固定表示"前台"，QSS `#KeyMode:checked` = `accent-soft` 激活态
  （与 16:9 那个 `#Toggle` 同一套观感）；点击即切通道并从当前播放头重启，
  选择落 `ui.key_play_mode`；
- **起播延迟**（v1.50 起为**全局**参数）：`key_play_delay_ms`（`assets/instruments.json`
  顶层，默认 3000ms，**所有乐器共用**；它描述的是"人切窗口要多久"，与弹哪把琴无关，
  所以不再按乐器配）。`_key_start_delay_ms()` 每次现读 `instruments.load_key_play_delay_ms()`
  （`(mtime,size)` 缓存，手改 JSON 后 F5 即生效），读不到时按 0 处理、绝不拦下演奏。
  点「演奏」开始、
  以及"暂停 → 继续"都要先走 `_schedule_key_start()` 倒计时，期间播放头不动、一个键都不发，
  消息区显示"x 秒后开始演奏…"。倒计时用单调时钟（`_delay_deadline`）+ 200ms 心跳，
  跳数不影响精度；`_cancel_key_delay()` 在停止/退出/换通道时清场，倒计时中再点 ▶ 视为
  "现在就开始"；
- **目标窗口**（v1.47）：`_key_target_hwnd()` = 框选区域中心窗口 → 当前前台 → 1s 采样的
  `_last_external_hwnd` → `inputsim.key_target_window()`（z-order 里前台下面第一个正常窗口，
  用 `is_app_window` 排掉本进程/工具窗/隐藏窗/最小化窗）。**后台通道必须有它**；
  **前台通道不需要**（`SendInput` 打给当前激活窗口）—— 句柄为 0 也照常起播（v1.48）；
- `_can_inject_now()`（v1.48，取代 `_rearm_key_sink`）：**只拦"真的投不出去"的情况**。
  后台看 `sink.ready()`（窗口还活着）；前台**恒 True** —— 发不出键由注入层逐拍跳过。
  旧版在这里返回 False 并暂停，等于"点「演奏」时前台必然是本程序 → 前台模式永远起不来"，
  正是 M6d 用户报的 bug。全程**不调 `activate_window`**（用户要求不要替人抢焦点）；
- **前台被挡 = 不暂停**（v1.48）：`KeyPlayer` 遇到 `ready()==False` 且
  `interrupt_when_blocked=False` → `on_blocked` → 控制器 `keys_blocked` 信号 → 主窗
  `_on_keys_blocked` 只在状态栏说一句"按键暂时不生效，演奏继续"。用户切到游戏窗口后
  剩下的音自然接上；
- **注入中断 = 暂停**（仅后台，v1.47）：`interrupted` 信号 → 主窗记 `_key_interrupted`，
  播放头停在最后高亮的和弦上；随后到来的 `idle` 被该标志拦下（`_on_playback_state`），
  **不退出演奏模式**；
- 频道偏好存 `settings.json` 的 `ui.key_play_mode`，**默认 `background`**（v1.47）。

**读入外部谱面 → 编辑框 tick 文本**（v1.48）：`tick_text_from_score(score, sustained=)`
按**目标乐器是否支持延音**（`spec.sustain_ms > 0`）决定要不要写 `[ms]` 后缀：

| 文件里的乐器 | 处理 |
|---|---|
| 风物之诗琴 / 镜花之琴 / 老旧的诗琴 / 悠可琴 / 余音（`sustain_ms == 0`） | **不写** `[ms]`（`A620D`）—— 这些乐器按下即发声，按住时长没有意义 |
| 谐律键琴（`sustain_ms = 300`） | 照旧写（`A[500]620D[60]`） |
| 没标 / 认不出 | 按**风物之诗琴**处理（默认无延音） |

文本生成后立即 `score_from_tick_text(text)` 重建 `_playback_score`：文本是唯一来源，
延音被裁掉时试听/演奏也不能偷偷带着旧延音（见 M6d 记录）。

### 10.4 配置热重载

```python
instruments.load_sampling()  ──► MainWindow._sampling
      _effective_inner_ratio() / _effective_square_side()

      CaptureWorker.set_sampler_options(inner_ratio, square_side, offset_y)
```

- `_JSON_CACHE` 用 `(mtime_ns, size)` 做签名，`instruments_mtime()` 判变没变；
- `_reload_instruments(source=, manual=)` 做四件事：换 `_sampling` → 重解析当前乐器（Δ 可能改）→ `_sync_sampler_options()` → 状态栏提示；**读坏了只 warning，不改变现有参数**；
- 触发点只有四个：启动（一次）、开始预览、学习基线、F5（手动，会明确回「没有变化」）；**运行期无后台轮询**；

- `_ensure_sampler()` 用 worker 自己的选项构造，参数变化即丢弃缓存重建。

### 10.5 乐器选择

- `assets/instruments.json` 数组顺序 = 下拉顺序，`id` 唯一；

- `settings.json` 的 `ui.instrument` 是「上次选中」；`_load_profile()` 仅在 `profile.instrument == 当前乐器` 时套标定；老档为空才沿用「按标定档切」；

| 字段 | 取值 | 说明 |
|---|---|---|

# 第三部分 · 测试与踩坑

## 15. 测试指导（给后续开发者）

**基本要求**：`pytest`，每个模块一个目录 `tests/unit_<模块>/`；测试**不得联网、不得依赖游戏运行**，一律用合成数据或仓库内的静态图/文本。

**分层建议**

| 层 | 怎么测 | 关注点 |
|---|---|---|
| 格式解析/序列化 | 用真实谱面文本 + 手工构造的边界串 | 往返一致（`parse(format(events))` 与 `events` 等值，浮点留 0.1ms 容差）；非法输入只产 warning 不抛；`[ms]` 延音三条容错；无 rest 的 `"AS"` 是一个和弦 |
| 算法（检测/采样/判按） | 合成的圆阵列、合成的 RGB 方波序列、静态参考图 | 网格校正的行列顺序（下→上）；圆数不符时原样返回；单帧抖动不触发、`confirm_frames=2` 只延迟确认不改时间戳；同键快速连击要补认而不是整段丢弃；`chroma/weighted` 必须各自有独立用例（否则掉进单通道分支也测不出来） |
| 播放/调度 | 假的 AudioEngine + 记录回调时刻 | 相对间隔正确、变速按比例、`play_from` 不重播已过去的音 |
| 导出 | 用**独立重实现**的上游规则解析自己的产物 | 别「自己验自己」；BGI 合规性回归在 `tests/unit_formats/test_bgi_conformance.py`，改导出逻辑必跑 |
| UI | `QWidget.grab()` 断言像素/文案；交互走信号 | 必须 `setenv("APPDATA", tmp_path)` 隔离配置；**offscreen 平台字体库为空、grab 全是豆腐块，验证文字要用默认平台** |

**改动前的红线回归**：判据（三处同改）、采样几何、`confirm_frames`、tick 序列化/解析、BGI 双向、进度条与键位回放联动 —— 这六块任何一处改动，先跑对应单测再手测一次实机。

**已备好的工具**（不要重复造）

| 工具 | 用途 |
|---|---|
| `tools/compare_sheets.py <A> <B>` | 谱面画像 + 往返保真度 + 跨文件比对 |
| `tools/bgi_sim.js` | 在 `vm` 里用虚拟时间跑 BGI `main.js`，比对 keyDown/keyUp 序列 |
| `tools/eval_reftex.py` | 用参考图批量评估键位检测（只看颜色，不能验收键位） |
| `tools/reftex_colors.py` | 参考图 → 每键 RGB/Δ → 建议 weights/refs/Δ |
| `out/probe_close_button.py` | Win32 探针（`IsHungAppWindow` + `SC_CLOSE` 菜单项态），排查「标题栏 X 置灰」 |

**已知测试环境限制**：`pytest -q` 结尾可能因 PySide6 offscreen 退出阶段 segfault 而拿不到汇总行，这是既有现象，用 `--collect-only` 数用例、看各用例 PASS/FAIL 判断。

**新增测试的判定标准**：能定位到具体函数、失败信息能直接指出口径（例如「gap 应按 onset 到 onset 计算」），而不是只断言最终字符串。

## 16. 踩坑清单

| # | 坑 | 规避 |
|---|---|---|
| 1 | Hough `param1/param2` 与常见默认相反 | 用运行时值 `20/40` |
| 2 | 网格校正输出顺序是「下→上」 | `circle_map_note` 前不要重复排序 |
| 3 | OpenCV 是 BGR，阈值参数按 R/G/B 语义给 | 统一转 RGB 再比较 |
| 4 | tick 无 rest 会粘连 | 生成端强制 rest ≥1ms |
| 5 | 延音两种写法（`A.500 S.500` / `AS`） | 解析器都要能吃；生成端固定一种 |
| 6 | 元数据只在首个 Chord/Rest 前生效 | `@name` 必须放文件头 |
| 7 | WGC 有黄色边框、可能含鼠标 | `draw_border=None, cursor_capture=None` |
| 8 | DXGI 抓不到受保护内容 | 黑帧检测 + 提示 |
| 9 | `mss` 在窗口化优化下可能失败 | 仅作兜底，失败自动降级 |
| 10 | DPI 缩放导致坐标偏移 | Per-Monitor DPI aware + 物理像素 |
| 11 | `pygame.mixer` 声道有限 | `set_num_channels(32)`，同键重触发先 stop |
| 12 | 窗口缩放后键位失效 | 监听尺寸变化 → 重算映射/提示重标定 |
| 13 | 视频源 4:2:0 色度失真 | 视频档单独标定；必要时双模板兜底 |
| 14 | `QImage(...)` 未 `.copy()` 会引用临时缓冲 | 生成 `QImage` 后立即 `copy()` |
| 15 | 剪 winrt 后隐藏导入被捞回 | hiddenimports filter 与 `EXCLUDES` 两处同改 |
| 16 | 按键演奏漏发 up = 游戏里琴键卡死 | 暂停/停止/中断/异常收尾都 `release_all()`，最后再 `force_release(keys_used())` 补一遍（多余的 up 无害） |
| 17 | 同键交叠重按被注入层吞掉 | 时间轴里前一段提前 30ms 抬起（`RETRIGGER_GAP_MS`）；但"刚好相接"不砍，否则延音白丢 30ms |
| 18 | 前台注入打进别的窗口 | `ForegroundKeys.ready()` 只看"当前激活窗口是不是**本进程**"：是就不发键（`SendInput` 打给当前激活窗口，抢焦点那套已废弃） |
| 19 | 前台模式点「演奏」就暂停，永远起不来 | 点按钮瞬间前台必然是本程序 → 那时如果判"不可注入"并暂停，就永远等不到游戏。改为**逐拍跳过**（`interrupt_when_blocked=False` + `on_blocked` 提示），演奏照走 |
| 20 | 中途起播听不到延音 | `_held_at(start, strict=True)` 补按仍应按住的键；`strict` 避免与同刻 down 重复 |
| 21 | 焦点离开游戏时发出的 up 打空，回来琴键还按着 | `ForegroundKeys._pending_up` 记账，切回来后 `key_down` 先 `_flush_pending_up()` 补发（多余的 up 无害） |
| 22 | 外部谱（midi/yuanqin）转出来全是 `A[500]` | 按目标乐器 `sustain_ms > 0` 决定写不写 `[ms]`；没标乐器按风物之诗琴（无延音） |

**按键演奏的时间轴约定（v1.45）**：

| 规则 | 语义 |
|---|---|
