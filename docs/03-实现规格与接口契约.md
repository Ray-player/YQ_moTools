## 1. 数据模型（`src/yqrec/types.py`，源码级）

```python
from __future__ import annotations
from dataclasses import dataclass, field

# ---------- 几何 / 捕获 ----------

@dataclass(frozen=True)
class Rect:
    left: int
    top: int
    width: int
    height: int

    @property
    def right(self) -> int: return self.left + self.width
    @property
    def bottom(self) -> int: return self.top + self.height

@dataclass(frozen=True)
class ScreenTarget:
    """任意屏幕区域（游戏 / 浏览器视频 / 播放器 / 桌面）"""
    monitor: int                 # 0 = 主屏
    rect: Rect                   # 屏幕物理像素（多屏时为虚拟桌面坐标系的绝对坐标）

@dataclass(frozen=True)
class WindowTarget:
    """绑定窗口（用于排除自身 HUD / 被遮挡）"""
    hwnd: int
    norm: tuple[float, float, float, float]   # 客户端归一化 (u0, v0, u1, v1)，0..1

CaptureTarget = ScreenTarget | WindowTarget

@dataclass(frozen=True)
class CaptureStats:
    fps: float
    dropped: int
    last_error: str | None = None

# ---------- 乐器 / 标定 ----------

@dataclass(frozen=True)
class KeyThreshold:
    """单通道阈值"""
    min_r: int = 0; max_r: int = 0
    min_g: int = 0; max_g: int = 0
    min_b: int = 0; max_b: int = 0

@dataclass(frozen=True)
class KeyArea:
    code: str                    # "main" / "chord"
    name: str
    channels: tuple[str, ...]    # ("R",) / ("R","G") …
    keys: tuple[str, ...]        # 该区域包含的键盘字母

@dataclass(frozen=True)
class KeyPoint:
    u: float; v: float; r: float   # 归一化中心 (0..1) + 半径（按 1920 宽归一化）

@dataclass(frozen=True)
class KeyGrid:
    points: tuple[KeyPoint, ...]   # 顺序 = NoteToKeyMap 顺序（行主序）
    key_count: int

@dataclass(frozen=True)
class InstrumentSpec:
    id: str; name: str
    key_count: int
    sustain: bool
    areas: tuple[KeyArea, ...]
    note_to_key: dict[str, str]      # "+1" -> "Q" …（顺序敏感，见 §3.3）
    note_to_audio: dict[str, str]    # "+1" -> "audio/YuanShen/fwzs/1+.mp3"
    default_thresholds: dict[str, KeyThreshold]   # area code -> threshold
    hough: dict[str, float]

# ---------- 采样 / 事件 ----------

@dataclass(frozen=True)
class RgbSample:
    ts: float                      # perf_counter 秒
    rgb: tuple[tuple[int, int, int], ...]   # (K, 3) 每键 (R, G, B)

@dataclass(frozen=True)
class PressEvent:
    key: str                       # 键盘字母
    down: bool
    ts: float

@dataclass(frozen=True)
class NoteEvent:
    keys: tuple[str, ...]          # 同拍按键
    onset_ms: float
    sustain_ms: float = 0.0        # 一期恒 0

@dataclass(frozen=True)
class RestEvent:
    ms: float

ScoreEvent = NoteEvent | RestEvent

@dataclass(frozen=True)
class Diagnostic:
    message: str
    offset: int
    length: int
    level: str                     # "error" | "warning"
```

**不变式（必须写进 `__post_init__` 或构造时校验）**

1. `NoteEvent.keys` 非空、无重复、均为 `note_to_key` 的值集；
2. `onset_ms` 单调不减；`sustain_ms >= 0`；
3. `KeyGrid.points` 长度 == `InstrumentSpec.key_count`；
4. 归一化坐标 `u,v ∈ [0,1]`。

## 3. 算法规格

### 3.1 坐标映射（两种目标）

```python
def target_to_frame_rect(target: CaptureTarget, frame_w: int, frame_h: int,
                         *, win_client: tuple[int,int,int,int] | None = None) -> Rect:
    """把目标换算成'当前帧内'的像素矩形。"""
    if isinstance(target, WindowTarget):
        u0, v0, u1, v1 = target.norm
        return Rect(round(u0*frame_w), round(v0*frame_h),
                    round((u1-u0)*frame_w), round((v1-v0)*frame_h))
    # ScreenTarget：帧就是该屏幕区域本身（后端已裁剪），整帧即目标
    return Rect(0, 0, frame_w, frame_h)
```

- **ScreenTarget + DXGI/GDI**：`open()` 时把 `rect` 传 `region=`/`grab()`，之后每帧就是该区域，无需再裁；
- **WindowTarget + WGC**：整窗帧 + 上面的归一化裁剪；
- **WindowTarget + DXGI/GDI**：`GetClientRect` + `ClientToScreen` 得到屏幕矩形，再当 ScreenTarget 用（窗口移动时重算，每 500ms 或 `EVENT_OBJECT_LOCATIONCHANGE` 时刷新）。

### 3.2 键位检测（Hough + 网格校正）

**Step 1 · 找圆**

```python
def detect_keys(frame: np.ndarray, hough: dict, key_count: int) -> list[Circle]:
    h, w = frame.shape[:2]
    s = w / 1920.0                              # 归一化基准
    y0 = int(h / 3)                             # 只取下面 2/3
    roi = frame[y0:, :]
    gray = cv2.cvtColor(roi, cv2.COLOR_BGR2GRAY)
    mask = cv2.inRange(gray, 0, int(hough["upper_bound"]))   # 239：挖掉高光 → 暗环
    circles = cv2.HoughCircles(
        mask, cv2.HOUGH_GRADIENT, dp=hough["dp"],
        minDist=hough["min_dist"] * s,
        param1=hough["param1"], param2=hough["param2"],
        minRadius=int(hough["min_radius"] * s),
        maxRadius=int(hough["max_radius"] * s),
    )
    if circles is None:
        return []
    out = []
    for x, y, r in circles[0]:
        out.append(Circle(float(x), float(y) + y0, float(r)))   # Y 加回偏移
    return out
```

> ⚠️ 参数（1920 宽基准）：`dp=2.0, minDist=80, param1=20, param2=40, minRadius=40, maxRadius=53, upperBound=239`。
> param1/param2 与常见默认（40/20）**相反**，以运行时的 20/40 为准。

**Step 2 · 网格校正**（逐行等价的伪代码）

```
输入：circles（长度必须是 7 的倍数且 >= 14，否则原样返回）
rows = len(circles) // 7
1. 按 Y 升序排序
2. 切成 rows 段，每段 7 个；每段内部按 X 升序
3. row_y[i]   = 第 i 段 7 个圆的 Y 平均值
4. col_x[j]   = 所有段中第 j 个（X 序）圆的 X 平均值
5. 每个圆 center = (col_x[j], row_y[i])，半径保留
6. 输出顺序：**倒序遍历段**（Y 最大的段先输出），段内按 X 升序
```

> 第 6 步的"倒序"很关键：网格校正输出的第一行是**画面最下面**那排。`circle_map_note` 依赖这个顺序。

**Step 3 · 圆 → 音名**

```
要求 len(circles) == key_count，否则抛 ValueError
1. 按 (Y, X) 排序（Y 主序）→ 行主序（上→下，左→右）
2. 若 key_count % 7 == 0：每 7 个一段，段内按 X 排序，再拼接
3. 依次与 note_to_key 的**键顺序**配对：
   note_to_key = {"+1":..., ..., "+7":..., "1":..., "7":..., "-1":..., "-7":...}
4. 返回 {note_name: circle}
```

> 结论：**最上一排 = 高音 `+1..+7`，中排 = `1..7`，下排 = `-1..-7`**。
> 若检测到的圆数与 `key_count` 不符 → 走手动点选（§3.2 兜底）。

**兜底：手动点选**

```
用户点 21 个点 → 按点击顺序同样走 Step 2 的网格校正（或直接按 7×3 均值吸附）
→ 得到 KeyGrid（归一化 u,v 与半径 r/W）
```

### 3.3 取色（ROI 均值）

对每个键位取 2R 方形区域的均值：

```python
def sample_key(frame: np.ndarray, cx: float, cy: float, r: float) -> tuple[int,int,int]:
    x0 = max(0, int(cx - r)); y0 = max(0, int(cy - r))
    w = int(r * 2); h = int(r * 2)
    w = min(w, frame.shape[1] - x0); h = min(h, frame.shape[0] - y0)
    if w <= 0 or h <= 0:
        return (0, 0, 0)
    roi = frame[y0:y0+h, x0:x0+w]                 # BGR
    b, g, r_ = roi.reshape(-1, 3).mean(axis=0)     # 注意 OpenCV 是 BGR
    return (int(round(r_)), int(round(g)), int(round(b)))   # 返回 (R, G, B)
```

**性能要求**：不要逐键 `reshape+mean`（21 次小数组运算）。预计算每键切片，按步长 4 降采样：

```python
class KeySampler:
    def __init__(self, grid: KeyGrid, frame_w: int, frame_h: int, stride: int = 4): ...
    def sample(self, frame: np.ndarray) -> np.ndarray:   # (K,3) uint8
        return np.stack([frame[sy, sx].reshape(-1,3).mean(axis=0)[::-1]  # BGR→RGB
                         for sy, sx in self._slices]).astype(np.uint8)
```

> 半径取 `ButtonConfig.Radius`（默认 47，按宽度缩放），**不是** Hough 输出的半径。

**外环采样（M2m，`detection.sample_inner_ratio > 0` 时启用）**：只统计
`inner_ratio·R .. 0.98·R` 的圆环，**跳过键帽中心的音符图标**。

为什么：图标像素在按下时几乎不变，留在均值里只是稀释信号；方形四角还混着背景。
实测同一个风物之诗（按下变青绿）：

| 采样口径 | 红叶树背景 信号/干扰 | 金黄花海背景 信号/干扰 |
|---|---|---|
| 整块 2R 方形 | 50 / 12.5 → **4×** | 32 / 2.6 → **12.5×** |
| 外环 0.55R~0.98R | 80 / 1.9 → **41×** | 55 / 2.1 → **27×** |

实现要点：掩膜按 `stride` 采样后的网格预计算（`np.arange(y0,y1,stride)`），
尺寸必须与切片 ROI 严格一致；掩膜为空时退回整块均值（避免除零）。
`inner_ratio=0` 保持旧行为，未标定的乐器不受影响。

### 3.4 判按（施密特触发）

判据：所选通道**全部**满足 `min <= v <= max`。

```python
class PressDetector:
    def __init__(self, spec, thresholds, *, min_hold_ms=25, min_gap_ms=30, hysteresis=0.15):
        ...
    def update(self, rgb: np.ndarray, ts: float) -> list[PressEvent]:
        """
        每键独立状态机（毫秒域）：
          enter[i]  = min_th
          exit[i]   = min_th + hysteresis * (max_th - min_th)
          未按下：v <= enter  → 候选按下（需持续 min_hold_ms 确认）
          已按下：v >  exit   → 抬起
        """
```

- 确认延迟：`min_hold_ms` 用来滤单帧噪声；实现上"事件时间戳"应记在**首次满足条件的时刻**，而不是确认时刻（否则整体偏移 min_hold）。
- `min_gap_ms`：同键两次按下之间最小间隔。
- 通道选择：`KeyArea.channels`；若为空，退化为"任一通道阈值 > 0"的通道。

**三种判据必须在状态机里分派（M2n 的教训）**：`_signals()` 只认 `max_drop` 与 `euclid` 时，
新增的 `chroma` 会掉进"单通道区间"分支 —— 而 chroma 阈值没有 `min/max`（全 0），
`_limits()` 返回 `None`，该键被**直接跳过**：表现就是"学完基线、无论怎么调灵敏度都一盏灯都不亮"。

| `KeyThreshold.mode` | 标量值 | 判按条件 |
|---|---|---|
| `max_drop` | `max(base_c − cur_c)` | `>= Δ` |
| `chroma` | `(cur_to − cur_from) − (base_to − base_from)` | `>= Δ` |
| `euclid` | `‖cur − base‖ / √n` | `>= Δ` |
| `channel`（旧） | 各通道值 | 全部落进 `[min, max]` |

> `KeyThreshold.accepts()` 与 `PressDetector._signals()` **两处都要分派**，它们各自被不同调用方使用
> （前者给校验/测试，后者给实时判定）。改判据时两处一起改。

### 3.5 事件装配

```python
def assemble(presses: list[PressEvent], *, chord_window_ms=25, guard_ratio=None,
             key_count: int) -> list[ScoreEvent]:
    """
    1. 把 up 事件按 key 与对应的 down 配对，得到 (key, down_ts, hold_ms)
    2. 按 down_ts 排序；相邻 down_ts 差 <= chord_window_ms 的合并为同一和弦
       （chord_window_ms 需小于最小音符间隔的一半）
    3. 和弦 sustain_ms（v1.35 延音）：乐器 sustain_ms==0 → 恒 0；
       否则取"hold >= sustain_ms"的那些键里最大的 hold（值为**完整**按住时长，
       不足阈值一律 0）。和弦内没有 per-key 延音，见 §5.3
    4. rest_i = onset_{i+1} - onset_i；最后一个和弦后不加 rest
    5. 场景保护：同一时刻按下键数 >= key_count - 5 → 整体丢弃并 warning
       （对照 BoMoExporter：list2.Count >= KeyCount - 5 时 continue）
    6. 若 rest_i < 1ms 且两和弦不同 → 强制写 1ms（见 §4.1，避免 token 粘连）
    """
```

### 3.6 tick 解析（状态机）

**语法（EBNF）**

```ebnf
document   = { blank | comment | rest | chord | unknown } ;
blank      = whitespace+ ;
comment    = "/*" { any } "*/" | "//" { any } "\n" ;
             (* 注释体内每行可含 "@key value" 元数据；仅出现在首个 rest/chord 之前才生效 *)
rest       = digit+ ;
chord      = note-char { [ "." duration-digits ] note-char } ;
             (* 注意：note-char 是任意字母；"." 后的数字属于该音符的延音 *)
unknown    = 其它字符（记 warning 诊断，跳过） ;
```

**解析语义**

```
for each token:
  Comment → 若尚未出现任何 Rest/Chord，则按行匹配 ^@(?<key>[A-Za-z][\w-]*)\s+(?<value>.+)$ 收集元数据
  Rest    → RestEvent(ticks=int(token))；非法数字 → error 诊断
  Chord   → 逐字符扫描：字母加入 keys；若后随 "."，读取其后 [0-9.]* 作为该音符延音，
            取值规则：只保留"比当前 sustain 更大"的值（最大值），否则忽略
            → NoteEvent(keys, sustain_ms=max)
  Blank   → 跳过（不产生事件）
```

**Round-trip 规则**：`parse(format(events)) == events`（浮点按 0.1ms 容差比较）。往返测试用 23 首 `DefaultSheet/*.txt`。

### 3.7 tick 序列化（本项目 canonical 形式）

序列化规则：

```
对每个事件：
  NoteEvent：
    - 若 sustain_ms >= 50：每个 key 写成 "X.<sustain>"，key 之间**用空格分隔**
      （`A.500 S.500` 空格分隔的写法解析回来是多个 NoteEvent，语义等价）
    - 否则：所有 key **直接连写**（如 "AS"）
    - 事件之间用空格分隔
  RestEvent：
    - 输出整数毫秒
    - 事件之间用空格分隔
```

**本项目生成端的两条硬规则**（tick 兼容性）：

1. **任何两个不同 onset 之间必须有一个 Rest 事件**（最小 1ms）；否则连写会被解析器合并成同一和弦；
2. 和弦内 key 拼接顺序 = `note_to_key` 顺序（`+1..+7, 1..7, -1..-7`），保证与既有 tick 工具链一致。

**推荐输出骨架**

```
/*
  @name <曲名>
  @instrument 风物之诗
*/
DBZ.731 731 MXB.731 731
```

### 3.8 fengwu 解析（只读）

fengwu 语法要点：

```
1. 头部：t = <float>，gc = <...>；缺省 t=0.22 并给 warning
2. 空格：连续空格 → Rest；但若空格后紧跟 "/" 或换行或文件尾 → 视为 Blank（不算 Rest）
3. "/" → 小节线（不产生事件）
4. "(" ... ")" → 和弦/分组（内部按字符解析为音名）
5. 字母 → 音名（A-Z，单向映射到 tick 的键位；注意 fengwu 的音名体系与 tick 不同，需转换表）
6. 每 1 个 Rest 计数 = 166 ticks（BaseTicksPerBeat）
```

> 一期只要求"能解析出可播放的事件"；容错策略：无法识别的 token 记 warning，不中断。

### 3.9 domiso 解析（只读，含 `.dms`）

domiso 语法要点（常量见 `DomisoScoreConstants` 语义）：

```
头部：bpm = <int>（默认 80）；1 = <A-G><oct?><#|b>（默认 1=C4 → BaseMidi=60）
音符正则：
  ^(?<arpeggio>~)?(?<scale>-*|\+*)(?<note>[0-7])(?<semitone>#|b)?(?<notelen>(?:/|-|\.)*)\s?$
音高 = BaseMidi + BaseOffset[note] + (scale_len * 12 带符号) + semitone(±1)
  BaseOffset = [0,0,2,4,5,7,9,11]   # 0 号位占位，1..7 对应 C D E F G A B
时值（beat = 60000/bpm ms）：
  base = beat
  "/"×n : base = base - current + current/2^n ; current /= 2^n
  "-"×n : base += beat * n ; current = beat
  "."×n : 每个附点：current *= 0.5; base += current
和弦 "()"：同 onset；连音 "{}"：合并时值；琶音 "~"：每个音延迟 ArpeggioDelayStep=40ms
rollback = <float>：时间轴回退
MIDI → 键盘字母：MidiToKey（只有自然音 48..83 的 21 个），黑键用 ±1 邻键 + 升降记号处理
```

### 3.4.1 确认帧数 `confirm_frames`（M2q.8，取代时间闸）

**结论**：判按确认不再由「毫秒」控制，而由「帧数」控制 —— 参数在**乐器**里：
`assets/instruments.json` → 每个乐器的 `detection.confirm_frames`（int，1~10，默认 **1**）。

| 值 | 含义 | 适用 |
|---|---|---|
| `1`（默认） | 条件首次成立即确认，＝「看到就认」 | 轻按/低帧率场景（推荐） |
| `2` | 连续 2 帧都满足才确认 | 特效/角色扫过造成零星误判时 |
| `3+` | 更保守 | 极端干扰，代价是确认更晚 |

- **事件时间戳仍取首帧**（`st.pending_since`），所以 `confirm_frames=2` 只是"晚一帧才认"，
  写进谱面的时刻与 `=1` 完全一致 —— 调它不影响谱面时序。
- 计数是**连续**的：中间只要有一帧不满足，`seen` 归零重新数（不是累计）。
- 越界（`<1` 或 `>10`）在解析时回落 1 并记 warning（`parse_detection`）。
- 改完存盘 → 按 **F5**（或重开预览/重学基线）生效：`_reload_instruments()` 会调
  `worker.set_spec()` 重建判按器；以前 F5 只换界面上的 spec，后台还在用旧参数。

**为什么弃用 `min_hold_ms`（时间闸）**

旧默认 `min_hold_ms=25` 的语义是「按下条件必须在**后续某一帧**仍然成立才确认」，
等价于「至少被两帧看到」，且与帧率强耦合：

| 处理帧率 | 帧间隔 | 确认需要 | 最小可见时长 |
|---|---|---|---|
| 60fps | 16.7ms | 第 3 帧（16.7 < 25） | ≈33ms |
| 30fps | 33ms | 第 2 帧 | ≈33ms |
| 20fps（GDI 回退） | 50ms | 第 2 帧 | ≈50ms |

**只占 1 帧的按下 100% 丢失**，低帧率下门槛还水涨船高 —— 现场症状就是"轻按漏识别"。
`confirm_frames` 的帧数语义与帧率解耦：不管一帧是 16.7ms 还是 50ms，都是"看 N 帧"。

**`min_hold_ms` 现在的定位**：`settings.json` 的 `record.min_hold_ms` 仍接线，
但降级为「无论帧率多高，至少按住这么久的绝对下限」，默认 `0`（不启用）、一般不要动。
去抖请用 `confirm_frames`。

**附：同键快速连击不再整段丢弃（M2q.8 顺带修）**

旧实现的确认条件把 `pending_since - last_up_ts >= min_gap` 也写在同一个 `if` 里，不满足就整段跳过，
而 `pending_since` / `last_up_ts` 之后都不再变化 → **只要一直按着，这个键永远判不出按下**。
快速连击同一个键（间隔 < `min_gap=30ms`）时，第二个音会被整个丢掉（不是延迟）。

现在改为：间隔不够就把 `pending_since` 推到当前帧重新数（`seen=1`），等够 30ms 再补认。

| 场景 | 旧行为 | 新行为 |
|---|---|---|
| 连击间隔 20ms，且第二个音按住 200ms | **不触发**（整段丢失） | 在上次抬起 +30ms 处触发一次 |
| 连击间隔 20ms，第二个音只占 1 帧 | 不触发 | 也不触发（不足 30ms 就结束了，属预期） |

**诊断**：`PressDetector.short_presses` 统计"刚好用满 `confirm_frames` 帧就确认"的按下次数
（`=1` 时即"只占 1 帧"），停止录制时写日志 —— 这个数大说明轻按多、帧率偏低；
若它是 0 却仍漏，问题在颜色阈值（该降 `delta`）而不是帧数。

### 4.9 取帧策略与实际帧率（M2q.4 实测）

| 环节 | 现状 | 说明 |
|---|---|---|
| 后端 | 默认 `dxgi`（dxcam）→ `gdi`；用户选 **j-HDR** 时 `hdr → dxgi → gdi`（`manager.FALLBACK_CHAINS`） | 屏幕区域一般走 dxgi；HDR 屏要用 j-HDR |
| 抓帧节奏 | `dxcam.start(target_fps=0)`（M2q.5 起 **不 pacing**） | DXGI 复制本来就被"桌面每秒 present 几次"限速；再叠一层 60Hz 定时器只会引入相位丢帧。实测 900×600/60Hz 屏：pacing 60 → 60.6fps，不 pacing → 63.8fps |
| 分析节奏 | **每拿到一帧就分析一次** | `_loop` 里 `sampler.sample()` + `_judge()` 无条件执行 |
| 预览节奏 | 每 3 帧转一次 `QImage`（`PREVIEW_EVERY=3` → 约 20fps） | 只影响画面刷新，不影响判定 |
| 面板节奏 | 每 3 帧发一次 RGB 快照（`SAMPLES_EVERY`） | 同上 |

单帧开销实测（1600×900、21 键、8 点环形）：采样 **0.55ms** + `to_qimage` 1.26ms（每 3 帧分摊 ≈0.42ms）
→ 60fps 的 16.7ms 预算只占 **≈6%**，所以**分析线程不是瓶颈**；实际帧率取决于后端与游戏本身。

**状态栏怎么读（M2q.5）**：`后端 | FPS: 处理帧率 | 源: xx.xfps(间隔ms) | 单帧 | 帧数`。
`源` 来自后端帧时间戳的中位间隔 —— 它才是"画面本身多少帧"。
`FPS ≈ 源` 且都 <45 时，状态栏会提示"源画面只有 N 帧，程序没有丢帧"（游戏里开 60 帧即可）；
`源 60 但 FPS 30` 才是程序侧在丢帧（此时看"单帧"耗时是否逼近帧间隔）。

> **打包坑（M2q.4 根因）**：`dxcam` 是延迟导入（`dxgi_backend._open` 里 `import dxcam`），
> PyInstaller 静态分析看不到 → 不入包 → `DxgiBackend.is_available()` 返回 False →
> **静默回退 GDI**（帧率骤降、短按被跳过）。修法：`yqrec.spec` 的 `hiddenimports`
> 必须 `collect_submodules("dxcam") + comtypes*`。启动日志会打印
> `捕获后端可用性: {'dxgi': True, ...}`，一眼可查。

### 4.10 多显示器与后端回退（M2q.6）

**坑**：dxcam 的 `create()` 默认只绑定**主输出**，而且 `region` 必须是**该输出的局部坐标**
（`_validate_region` 要求 `0 <= left < right <= width`）。我们的框选区域是**虚拟桌面全局坐标**，
区域落在副屏时全局 x 是负的 → `ValueError: Invalid Region` → dxgi 打开失败 →
`CaptureManager` 静默回退 gdi（用户只看到"选了 dxgi、状态栏却是 gdi"）。

**做法**（`capture/dxgi_backend.py`）：

| 步骤 | 实现 |
|---|---|
| 找输出 | `find_output(dxcam, cx, cy)`：遍历 `(device_idx, output_idx)`，用 `cam._output.desc.DesktopCoordinates` 判断哪个输出包含区域中心 |
| 换坐标 | `local_region(rect, origin, size)`：全局 → 局部，并夹进输出边界（跨屏时取交集） |
| 建相机 | `dxcam.create(device_idx=…, output_idx=…, output_color="BGR")` 后用局部 region `start(target_fps=0)` |
| 旧版兜底 | 拿不到 `Desc` 时退回"主输出 + 全局坐标"，并记 warning |
| 找不到 | 抛 `RuntimeError("没有 DXGI 输出包含区域中心 …")`（区域在已拔掉的屏上） |

**回退不再静默**：`CaptureManager.start_errors` 记录每个后端的失败原因（`["dxgi: Invalid Region: …"]`），
`CaptureWorker.backend_fallback` 信号把它送到界面：红字 + 状态栏提示
「「dxgi」打不开，已回退到 gdi：…」；同时状态栏后端名后面标 **（回退）**。

实测（本机双屏，主 1920×1080 + 副 2560×1440）：
副屏区域 `(-2400,200,1000,600)` → 输出 origin `(-2560,0)` → 局部 `(160,200,1160,800)`；
`CaptureManager.start(prefer="dxgi")` 返回 `dxgi`、`start_errors == []`，两个屏都能抓。

### 4.11 j-HDR 后端与回退链（2026-10-22）

**背景**：HDR（或 Win11 24H2 的 ACM）开启后 DWM 合成到线性 scRGB FP16，`DuplicateOutput` /
BitBlt 都被**截断**成 8bit → 灰阶塌陷 → 「键帽压暗差值」判据失效。调研与三种方案对比见
`01 §14`（HDR 截图方案技术总结，原 docs/05）；最终选用现成轮子 `j-hdrcapture`（`DuplicateOutput1` 取 FP16 +
按每屏 SDR 白电平在 GPU 归一 + 高光按最亮通道缩放保色相）。

**新档位**：界面「后端」下拉 = **`j-HDR`（默认）/ `dxgi` / `gdi`**（M3e 起默认改为 j-HDR），选择存在 `settings.json` 的 `backend`（值 `hdr` / `dxgi` / `gdi`）。
**默认顺序**：`default_backends()` = `[hdr, dxgi, wgc, gdi, printwindow, file]`；`CaptureManager` 不带 `prefer` 时（CLI `--backend auto`）也走这条。

| 项 | 实现 |
|---|---|
| 模块 | `capture/hdr_backend.py::HdrBackend`，`name="hdr"`，显示名 `j-HDR`（`manager.backend_label`） |
| 会话 | `hdrcapture.Capture(timeout_ms=16)` 常驻；**DXGI 同一输出只允许一个 duplication 会话**，与 dxcam 互斥（管理器切换会先 close） |
| 区域 | 直接用全局物理坐标 `grab_region(l,t,w,h)`；`pick_monitor()` 要求区域**完整落在单块屏**内，跨屏直接拒绝并回退（否则库会去合成整个虚拟桌面） |
| 输出 | `frame.bgr` → `HxWx3 uint8`（BGRA 在库内已剥掉）；时间戳 `perf_counter()` |
| 首帧 | 没有真实 present 时抛 `InitialFrameTimeout` → **返回 None**（计丢帧，不逼降级）；`AccessLost` / `DimensionsChanged` → `RuntimeError`（让管理器回退/重建） |
| 失败话术 | `start_errors` → `backend_fallback`：「「j-HDR」打不开，已回退到 dxgi：…」 |

**回退链**（`manager.FALLBACK_CHAINS`，稳定排序，不在链里的排到最后）：

| 用户选择 | 回退顺序 |
|---|---|
| `j-HDR` | `hdr → dxgi → gdi` |
| `dxgi`（默认） | `dxgi → gdi`（**不会**偷偷用 hdr，免得换了后端没人知道） |
| `gdi` | `gdi` |

**选择持久化（M3e）**：`settings.json` 的 `backend` 是唯一真相 ——
`_combo_backend.currentIndexChanged → _on_backend_changed()` 立刻写盘，启动时
`findData(cfg.backend)` 还原；**标定档 `profiles/default.json` 的 `backend` 只作记录，不再覆盖它**
（否则每次启动都会被拽回标定时的旧值）。`CONFIG_VERSION 3 → 4`：v4 之前的档里 `backend`
是 `to_dict()` 序列化出的默认值（UI 从不回写，不是用户选择）→ 迁移时强制置 `hdr`。

**打包**：`hdrcapture` 同样是延迟导入，`build/yqrec.spec` 的 `hiddenimports` 必须显式加
`"hdrcapture"`；产物落在 `_internal/hdrcapture/hdrcapture.pyd`。启动日志 `捕获后端可用性:
{'dxgi': True, 'hdr': True, ...}` 可一眼确认。

> **切 HDR / 切后端后必须重学基线**：颜色映射变了，旧基线拿来比会一直判错（已写进《使用说明》）。

## 5. 文件格式 schema

### 5.1 `assets/instruments.json`（`version: 4`）

**三段职责分明**：`sampling`（全局几何）→ 乐器上层 `delta`（灵敏度）→ `detection`（判据 + 参考色）。
另有全局参数 `record_click`（录制启动输入注入模式，所有乐器一致）。**数组顺序 = 界面乐器下拉顺序**；`id` 必须唯一。

```jsonc
{
  "version": 4,
  "sampling": {                       // ★ 全局采样几何，所有乐器统一调用（M2p）
    "ring_width_ratio": 0.43,         //   环带宽 × R → 内径 = 0.98 − 0.43 = 0.55R
    "square_side_ratio": 1.0          //   小方块边长 × R（M2p 从 2R 减半；0.5R 半边长）
  },
  "record_click": 2                    // ★ 全局：录制启动输入注入模式（M3g，int）
                                       //   0=不启用 1=激活窗口+空格 2=鼠标点击；代码侧缺省=0
  "instruments": [
    {
      "id": "fwzs", "name": "风物之诗", "key_count": 21,
      "sustain_ms": 0,                // ★ v1.35：延音阈值毫秒（0=不延音；>0=按住达标才算延音）
      "button_radius": 54,            // 1920 宽下的键半径；归一化时 /1920
      "delta": 30,                    // ★ 该乐器的灵敏度 Δ（M2p 从 detection 提到这里）
      "detection": {                  // 判据与参考色：改这里即可，不用改代码
        "metric": "chroma",           // max_drop | chroma | euclid | channel
        "channels": ["R", "G", "B"],
        "unpressed_ref": [246, 242, 231],
        "pressed_ref":   [163, 228, 206],
        "note": "米白盘→青绿盘：按下时只有 R 明显下降（G 升高），用『绿相对红变强』判按 …",
        "confirm_frames": 2           // ★ v1.35：默认 2（至少两帧确认；1=看到就认）
      },
      "areas": [{ "code": "main", "channels": ["R"], "keys": ["Q","W","E","R","T","Y","U","A","S","D","F","G","H","J","Z","X","C","V","B","N","M"] }],
      "note_to_key": { "+1":"Q","+2":"W","+3":"E","+4":"R","+5":"T","+6":"Y","+7":"U",
                       "1":"A","2":"S","3":"D","4":"F","5":"G","6":"H","7":"J",
                       "-1":"Z","-2":"X","-3":"C","-4":"V","-5":"B","-6":"N","-7":"M" },
      "note_to_audio": { "+1": "audio/fwzs/1+.mp3", "...": "..." }
    },
    { "id": "xljq", "name": "谐律键琴", "sustain_ms": 300, "delta": 20,
      "...": "同上结构，音频 audio/xljq/；按住 >=300ms 才把 [ms] 写进谱面" },
    { "id": "yy",   "note": "余音：areas 含 main + chord（chord 前缀 +）" }
  ]
}
```

**★ 两个全局旋钮（`sampling`，所有乐器共用）**

| 字段 | 含义 | 默认 | 换算 |
|---|---|---|---|
| `ring_width_ratio` | 环形**环带宽**（× R） | `0.43` | 内径 = `0.98 − 0.43 = 0.55R`，外径固定 0.98R |
| `square_side_ratio` | 小方块**边长**（× R） | `1.0` | 半边长 = `0.5R`；M2p 之前是 `2.0`（整块 2R） |

- 校验：环宽 ∈ `[0.05, 0.96]`、边长 ∈ `[0.1, 4.0]`，越界回落默认并记 warning（不抛异常）。
- **`0.98 − ring_width` 是设计上的耦合**：外径固定（避开键帽描边/抗锯齿），所以"环宽"是唯一旋钮。

**★ `record_click`（全局录制输入注入，M3g；int 模式）**

| 值 | 含义 | 默认 |
|---|---|---|
| `0` | 不启用，录制启动前不注入任何输入 | 代码侧缺省 `0` |
| `1` | 把**框选区域所在窗口**激活为前台后模拟一次**空格**（激活失败坚决不发） | 发布 JSON 显式 `2` |
| `2` | 在**框选区域中心** SendInput 一次左键（点完恢复光标） | |

- 实现：`yqrec/inputsim.py`——`left_click()`（模式 2）/ `window_at()` + `is_own_window()` + `activate_window()` + `press_space()`（模式 1）。前台 SendInput，坐标 = 全局物理像素；激活流程抄 MAA `ForegroundUtils.h` 三段式（提层 → SetForegroundWindow → 复核，失败 TOPMOST↔NOTOPMOST 强提后再复核），调研见 `docs/06`。
- 执行顺序：`MainWindow._start_recording()` → `_record_click_warmup()`（按模式分发）→ `worker.start_recording()`——**注入发生在开始录帧之前**，不会进谱面。
- 模式 1 安全阀：`GetForegroundWindow()==目标` 复核通过才发空格；命中**本程序窗口**（`is_own_window`/自身 winId）不发——否则空格落回「录制」按钮会立即误停录制。
- 门控：模式 `0` 不注入 / 未框选区域跳过 / 注入或激活失败只记日志+状态栏提示，**绝不拦录制**。
- 解析：`instruments.load_record_click()` 返回 int；兼容旧写法 `{"enabled": true/false}` → `2/0`（记 info 提示迁移）；缺段/非法值一律回落 `0`（与 sampling 同风格）。
- 改完**不用重启，但要触发一次重读**（M2q.2 起不再定时轮询）：启动时读一次，
  之后在「开始预览」「学习基线」时顺手比对 mtime，或直接按 **F5** 强制重读。
  重读会换口径 + 推给 worker + 状态栏提示"参数有变请重新学基线"。
  打包后改的就是 `dist/YQRec/_internal/assets/instruments.json`。

> **为什么把 Δ 提到乐器上层**：开发者调参时最常改的就是它。原来埋在 `detection.default_delta` 里，
> 六个乐器扫一眼要展开六层；现在 `{"id": "fwzs", "delta": 30}` 一行就能读到。
> 兼容：v2 文件把 Δ 写在 `detection.default_delta` 里仍可读（乐器层级优先）。

**已标定的 detection（Δ 见各乐器 `delta` 字段）**

| 乐器 | 判据 | 未按下 ref | 按下 ref | 特征变化 | Δ | 信号 / 干扰 |
|---|---|---|---|---|---|---|
| `fwzs` 风物之诗 | **chroma** | 246,242,231 | 163,228,206 | 按下时 R 明显下降、G 升高（绿相对红变强） | 30 | 55–80 / 1–2 |
| `xljq` 谐律键琴 | max_drop | 247,242,230 | 218,196,155 | R −29 / G −46 / B **−75** | 40 | 75 / — |

**三种采样口径的实测对比（谐律键琴真图，Δ=40）**

| 几何 | 按下信号（`+2` / `7`） | 未按下最大干扰 | 说明 |
|---|---|---|---|
| 整块 2R 方形（M2p 前） | 49 / 64 | 7 | 四角掺背景，信号被稀释 |
| **1R 方形（M2p 默认）** | **54 / 74** | **16** | 更贴键帽；背景"稀释"少了，干扰也涨 |
| 环形 0.55R~0.98R（UI 默认） | 76 / 79 | 3 | 信噪比最高 |

> 结论：面积减半后信号反而更强，Δ=40 仍安全（干扰 16 < 40），所以没有重标。

> **`chroma` 判据（v1.15）**：`(to − from)_当前 − (to − from)_基线`，方向 `(from→to)` 由 refs 自动推出
> （风物之诗 R→G）。为什么需要它：风物之诗的键帽是**半透明**的，背景越亮盘面越亮，
> 绝对跌幅被压缩 —— 同一个乐器在金黄花海背景下跌 28、在红叶树背景下跌 69，
> `max_drop` 用一个 Δ 覆盖不了；而"相对色偏"在两景下都是 33~46，Δ=30 通吃。
>
> **ref 必须按运行口径标定**：`refs` 是**环形口径**（0.55R~0.98R）实测的。
> 换成小方块口径后均值会变（含中心图标与四角背景），需要用「学习基线」重新贴合。
>
> **`max_drop` 不必挑通道**：它取三通道最大跌幅，谐律键琴落在 B —— 同一份判据通吃。
>
> `button_radius` 是"1920 宽下的像素半径"：1069 宽的截图实测键半径 30px → `30×1920/1069 ≈ 54`。

### 5.2 应用配置 `%APPDATA%\YQRec\settings.json`

```jsonc
{
  "version": 1,
  "target": { "kind": "screen", "monitor": 0, "rect": [0,0,1600,900] },
  "backend": "auto",
  "profile": "game_fwzs",
  "ui": {
    "language": "zh-CN", "theme": "dark", "hud": true,
    "always_on_top": true,              // M2b：图钉按钮，默认置顶
    "window_width": 558, "window_height": 913,   // 关闭前的窗口尺寸（默认 = 实机窄长条）
    "window_maximized": false,          //      最大化只记标志，不覆盖普通尺寸
    "window_x": 1393, "window_y": 50,   // 关闭前的窗口位置（默认主屏右下贴边；-1,-1 = 不定位）
    "sample_mode": "ring",              // M2o：ring（外环）| square（整块 2R 方形）
    "square_offset_y": 0                // M2o：方块模式的纵向偏移，单位 = 1920 宽基准像素
  },
  "paths": { "last_score_dir": "D:/谱面" },
  "audio": { "volume": 0.8, "offset_ms": 0 },
  "record": { "hotkey": "F9", "chord_window_ms": 25, "min_hold_ms": 0, "min_gap_ms": 30 }
}
```

> `load_config()` 的**段合并列表**必须包含 `ui` / `paths` / `audio` / `record` / `target`，
> 新增段时漏加会导致"写进去了但读不回来"（v1.8 踩过）。

**三个配置文件的分工（不要混）**

| 文件 | 位置 | 内容 | 谁写 | 何时读写 |
|---|---|---|---|---|
| `settings.json` | `%APPDATA%\YQRec\` | **本机 UI 状态**：窗口尺寸/位置/最大化、置顶、检测方式、保存目录、音量 | 程序（用户操作时） | 启动读**一次**；缩放/移动/切开关时防抖写 |
| `profiles/default.json` | `%APPDATA%\YQRec\profiles\` | 标定结果：框选区域、21 个键位、**逐键基线**、阈值 | 程序 | 启动读一次；标定后写 |
| `assets/instruments.json` | 程序目录（打包后在 `_internal/assets`） | **识别参数**：乐器、Δ、权重、死区、采样几何、音频映射 | 人（也可由「半径」滑条写） | 启动读一次 + 按需重读（M2q.2） |

**首次运行的默认窗口状态（M2q.7）**

`settings.json` 不存在时，`default_config()` 直接给出用户实机调好的那一套，**不需要重新摆窗口**：

| 字段 | 默认值 | 说明 |
|---|---|---|
| `window_width` / `window_height` | **558 × 913** | 窄长条竖排；558 = 当前布局能落地的最窄宽度（布局最小宽 554，早期记的 520 会被 `_clamp_window_size()` 抬高） |
| `window_x` / `window_y` | **1393 / 50** | 主屏（1920×1032 可用区）右下贴边；不在屏内时 `_restore_window_position()` 会拉回主屏居中 |
| `window_maximized` | `false` | 只记标志，不覆盖普通尺寸 |
| `always_on_top` | `true` | 贴游戏用 |
| `record.min_hold_ms` | `0` | 可选的绝对时长下限（不启用）；去抖用乐器的 `detection.confirm_frames`，见 §3.4.1 |

常量集中在 `config.py`（`DEFAULT_WINDOW_*` / `DEFAULT_MIN_HOLD_MS`），`UiConfig` 与
`ui/main_window.py` 都引用它 —— 改一处即可，不会再出现"两处默认值不一致"。

**配置版本迁移（`CONFIG_VERSION`）**

`load_config()` 先跑 `_migrate(data)` 再填 dataclass，规则只做「旧值已失去意义」的迁移：

| 版本 | 迁移内容 | 为什么 |
|---|---|---|
| 1 → 2 | `record.min_hold_ms` 强制重置为 `0` | 旧版把它固定写死 25ms（"至少两帧可见才确认"）。M2q.4 改成默认 0 后，文件里残留的 25 会让修复**静默失效** —— 用户实测确实还在漏轻按，所以按版本号对齐 |

> 迁移**只在内存生效**，`save_config()` 时才落盘（不偷偷改用户文件）；迁移后 `version` 写成当前值，
> 避免每次启动重复迁移。用户在新版本里手动调过的值（如 `min_hold_ms=40` 防特效误触）不会被覆盖。

> **为什么不把窗口尺寸/位置/置顶塞进 `instruments.json`**：
> ① 它随程序分发，升级/重打包会整份覆盖 → 用户的窗口位置和置顶状态被重置；
> ② 它可能在只读目录（Program Files）→ 写失败；
> ③ 它是"乐器识别参数"，手改和版本管理都要干净，混进机器相关的 UI 数值只会让两边都难读；
> ④ 同机多用户会互相覆盖窗口位置。
> 想让配置跟着 exe 走，正确做法是"便携模式"（把整个 `%APPDATA%\YQRec` 挪到 exe 同级），
> 而不是把两类数据塞进同一个文件。

## 6. 错误码与诊断

| 码 | 场景 | 处理 |
|---|---|---|
| `E_CAPTURE_OPEN` | 后端打不开（权限/驱动/窗口消失） | 提示换后端/改窗口模式 |
| `E_CAPTURE_BLACK` | 连续 20 帧全黑 | 提示 DRM / 独占全屏 / 关"窗口化优化" |
| `E_KEYGRID_MISMATCH` | Hough 圆数 ≠ key_count | 自动转手动点选 |
| `E_CALIB_LOW_SNR` | 某键 `Δ/std < 2.5` | 标红该键，提示换角度/关滤镜 |
| `E_PARSE` | 谱面语法错误 | 编辑器定位到 offset |
| `E_EXPORT` | 导出失败（权限/路径） | 提示路径 |
| `W_TOKEN_MERGE` | 两和弦无 rest（会被合并） | 自动补 1ms rest + 提示 |
| `W_SUSTAIN_DROPPED` | 风物谱导出丢失延音 | 导出前确认对话框 |

## 7. 线程与数据流约定

| 线程 | 拥有者 | 允许操作 |
|---|---|---|
| 后端捕获线程（库内部） | 库 | 只产帧 |
| 分析线程 | `Session` | 读最新帧 → 采样 → 检测 → 追加 L1；**唯一写 `samples`** |
| UI 线程 | Qt | 只读快照（预览帧/统计/事件），不得直接调捕获 |
| 音频线程 | pygame | 只播声音 |

跨线程通信：`queue.Queue(maxsize=1)` 传"最新预览帧"，覆盖式写入（`get_nowait` 清空旧值）。

### 12.3.1 试听控制条（M2q.9）

| 控件 | 图标/文字 | 行为 |
|---|---|---|
| 快退 | ⏪（`media_icon("rewind")`） | **只在暂停时可用**；单击退一个和弦，按住（`autoRepeat` 420ms/90ms）连续退；只移高亮、**不发声** |

- 继续播放：`_cursor == _paused_at` → `resume()`（时间轴冻结过，音频无缝）；
  否则 `play_from(_cursor)`（位置被快进/快退动过，必须重开）。

  `_exit_play_mode()` 收起控制条，紧接着的 `playing` 又因为已退出模式被忽略 ——
  现象就是「点一下播放键，试听模式退出又切回来」。`PlaybackController._suppress_state`
  在「停旧 + 建新」整段为真，`player.play()` 放在解除抑制之后调用。
- **播放/暂停键不能开 `autoRepeat`**：按住 >420ms 会连发 `clicked`，反复播放↔暂停。

## 13. BetterGI（AutoYuanQin）曲谱互转（M2c）

### 13.1 格式事实（已核对脚本源码，勿凭印象改）

BetterGI 的「原琴 AutoYuanQin」支持三种 `type`：`yuanqin`（五线谱/简谱制谱器）、`midi`（MIDI 制谱器）、
`keyboard`（网络键盘谱）。**本项目支持 `midi` 与 `yuanqin`**：前者是纯时间事件流，与我们的 `Score` 同构；
后者是音符时值记号（`A[4]` / `(ASD)[8]` / `@[2]`），社区曲谱绝大多数是这种。`keyboard` 仍是隐式节奏
（不断言时值），暂不支持。

`type: "midi"` 曲谱结构：

```jsonc
{
  "name": "卡农", "author": "MidiTrans", "instrument": "风物之诗琴",
  "bpm": "120", "ticks": 480, "type": "midi",
  "description": "", "time_signature": "4/4", "composer": "", "arranger": "",
  "notes": "DZ338|DE39|UZ326|DB45|..."   // | 分隔的事件序列
}
```

单个 token：`^([DU])([A-Z@]+)(\d+)$` —— `D`/`U` = 按下/抬起，中间是**游戏键名**（多个字母 = 和弦，
`@` 表示空拍），末尾 = **执行本事件之前先等待多少 tick**。

> **方向问题（最易搞反）**：`main.js` 的 `play_sheet()` 里是 `await playbackSleep(wait)` **然后**才
> `keyDown/keyUp`，所以数字是"**本事件之前**的间隔"。用仓库里的真实曲谱验证：按"之前"解释，键的保持
> 时长是 153–1580ms（中位 360ms）；按"之后"解释会出现 18 个 0–18ms 的假保持。导出必须按"之前"写。
> 另外 `*120` 这种 token 是 BPM 变速标记（解析时要改 `base_time`）。

时间基准：`ms_per_tick = 60000 / (bpm * ticks)`。BGI 自带曲谱用 `bpm=120, ticks=480`
（1 tick ≈ 1.0417ms）；**本项目导出用 `bpm=125, ticks=480` → 1 tick = 1ms**，`onset_ms` 可直接当 tick 用，
零量化损失（`midi` 类型下 bpm 只是时间基准，不影响任何记号）。

### 13.2 导出规则：`Score` → BGI（`formats/bgi_sheet.py`）

1. **事件展开**：每个 `NoteEvent` 的每个键 → 一条 `down`（onset）与一条 `up`（onset + hold）。
2. **保持时长** `hold`：`sustain_ms>0` 用它（二期延音），否则用 `DEFAULT_HOLD_MS=60ms`；
   并且**只按同一个键**的下一次按下裁剪（留 `MIN_REPRESS_GAP_MS=30ms`）。
   不同键之间允许重叠 —— BGI 是事件流，能表达"低音按住、旋律在上方走"的多声部；
   若按和弦整体裁剪会把外部曲谱压成单声部（实测往返失真）。
   > 为什么是 30ms：脚本里 `lowest_latency = 30`，间隔 <30ms 会被"补足延迟"强行拉到 30ms，
   > 反而改变节奏；取正好 30ms（判断是 `>=`）走正常分支，且保持时长损失最小。
   > **注意 BGI 自己还会再提前 30ms**：当本 token 是 `U`、下一个 token 是 `D` 且键有交集时，
   > `main.js` 会 `await playbackSleep(wait_time - lowest_latency)` 再抬键 —— 所以文件里
   > 留 30ms 的同键间隔，实际演奏约 60ms。方向是"多留一点、绝不吞音"，接受这个代价。
3. **排序**：按 `(time, down 先于 up, key)` 稳定排序。
4. **分组**：同一 tick 且同状态的键合成一个 token（和弦），键按乐器 `key_order` 排序。
5. **tick 化**：`tick_i = round(t_i / ms_per_tick)`；token 的数字 = `tick_i - tick_{i-1}`（≥0）。
   用**绝对位置差分**而非每条四舍五入，避免累计漂移。
6. **首 token** 的数字 = `tick_0`（BGI 的前奏延迟），曲谱从 0 开始则为 `0`。
7. **元数据**：`type="midi"`、`ticks=480`、`bpm="125"`、`instrument` 用 BGI 显示名
   （`fwzs→风物之诗琴`、`jhzq→镜花之琴`、`ljdsq→老旧的诗琴`、`ykq→悠可琴`、`yy→余音`）、
   `name` 默认取文件名（BGI 要求文件名与 `name` 一致）。
8. 一期没有休止符：节奏全部由"事件前的等待"表达，不产生 `@` token。

示例（A 后 500ms 弹 D+F 和弦，各保持 60ms）：

```
DA0|UA60|DDF440|UDF60
```

> **数字是增量不是绝对时刻**：`DA0|UA800|DDF200` 里 A 抬起在 800ms、DF 按下在 1000ms。
> 校验时必须逐 token 累加（`tests/test_sustain_recording.py::_bgi_events` 就是这么做的）。

### 13.2.1 `type: "yuanqin"` 的延音表达（v1.35 起，v1.36 修正量化）

yuanqin 的每个 token = **按下 → 按够时值 → 抬起**，所以：

| 能表达 | 不能表达 |
|---|---|
| 单音的**延音时长**（时值 = keyUp 时刻） | **叠音**：一个键还按着、另一个键就响（token 是顺序播放的） |
| 和弦同时按下（`(AD)[4]`） | 延音超过"下一个音的起点"（会被截断） |
| 任意休止（`@[n]` 拼出来） | 任意毫秒的精确时值（只能取 `1/1.5/2/3/4…` 档） |

实现要点：

1. 时值上限：不延音乐器 100ms（`YQ_MAX_HOLD_MS`）；延音乐器 4000ms
   （`YQ_MAX_HOLD_MS_SUSTAIN`，实际受时值表最大档约束，bpm=300 时 1200ms）；
2. 取档用 `_yq_nearest_ms()`（**就近**，不再向下取整）：长音附近相邻档差 200~400ms，
   向下取整会砍掉两成以上（实测 750ms → 600ms）；就近取 800ms，误差减半；
3. `upper` 硬边界 = 下一个音的起点（同键再留 30ms），所以"就近向上"也不会让后续 onset 漂移；
4. `yuanqin_sustain_loss(score, spec) -> SustainLoss(count, max_ms)`
   统计"会被截短多少"（叠音 + 量化），UI 在保存 yuanqin 成功后用 warn 提示
   "N 处延音被截短（最长 Xms），要完整延音请改存 BGI · midi"。

> 结论：**延音要完整保留请导出 `midi`**（1 tick = 1ms，逐键 D/U，支持多声部）；
> yuanqin 只能表达单声部的延音，用于"给五线谱制谱器"的场景。

### 13.2.2 为什么 yuanqin"只能一个一个播放"（源码证据）

README 只写了记号规则，没直说播放模型；证据在同仓库的 `repo/js/AutoYuanQin/main.js`
`play_sheet` 的 yuanqin 分支主循环里（v3.8.x）：

```js
for (let i = 0; i < sheet_list.length; i++) {
    ...
    if (sheet_list[i]["spl"] === 'none') {          // 单音 / 休止 / 和弦
        let sleep_time = ...;                        // 这个 token 的时值
        if (sheet_list[i]["chord"]) {
            await play_chord(sheet_list[i]["note"], "down");   // 按下
            await playbackSleep(sleep_time);                   // 按够时值（阻塞）
            await play_chord(sheet_list[i]["note"], "up", flag);// 抬起
        } else if (sheet_list[i]["note"] === '@') {
            await playbackSleep(sleep_time);                   // 休止：只等待
        } else {
            await play_note(sheet_list[i]["note"], "down");
            await playbackSleep(sleep_time);
            await play_chord(sheet_list[i]["note"], "up", flag);
        }
    }
}
```

- 每个 token 都是 **按下 → `await playbackSleep(时值)` → 抬起** 的阻塞序列，`await` 期间不会
  进入下一个 token → **跨 token 无法叠音**；能同时响的只有 `(...)` 和弦内部的几个键。
- 时间轴完全由 token 时值累加而成，所以"长音 + 别的音同时开始"必须拆成
  「长音 → 休止 → 下一个音」，长音只能占到下一个音的起点。
- README「五线谱制谱器 · 附」也侧面印证：*"按键模式默认为按下后即刻抬起……该类按键需要
  结合休止符来实现按下和抬起之间的时间间隔"* —— 时值/休止是唯一的时间表达手段。

对照 `midi` 分支：相同位置是 `D`→`keyDown`、`U`→`keyUp`，不同键只有收到自己的 `U` 才抬起，
所以 **midi 天然支持叠音**（这也是谐律键琴导出应选 midi 的根据）。

**合规性回归**：`tests/unit_formats/test_bgi_conformance.py` 把上面两条规则（midi 的
`/^([A-Z])([A-Z@]+)(\d+)$/` + `60000/(bpm*ticks)`；yuanqin 的 `round(symbol_time*symbol/type)`）
**独立重实现**一遍，再用它去解析我们的产物 —— 不是"自己验自己"。2026-10-22 起 20 条全绿。

### 13.3 导入规则：BGI → `Score`

**`type: "midi"`**

1. 只接受 `midi` / `yuanqin`，其余抛 `BgiSheetError`（提示暂不支持）。
2. 逐 token 累加 `cursor += n * ms_per_tick`（先等后按），再登记 `down` 时刻 / `up` 时配对。
3. 同一时刻（±5ms）按下的键合成一个 `NoteEvent`；`sustain_ms` = 该和弦内最大保持时长。
4. `*120` 变速标记：切换到新 bpm 后重算 `ms_per_tick`（后续 token 用新基准）。
5. 非法 token 跳过并记 warning（社区曲谱质量参差，不能整曲失败）。
6. 元数据：`name/instrument/author` 进 `metadata`，`instrument` 用反查表映射回本地乐器 id。

**`type: "yuanqin"`**（`parse_yuanqin`）

7. 记号：`A[8]` 单音、`(ASD)[4]` 和弦、`@[2]` 休止、`%[72]` 变速标记；`[4-*]` 附点、`[16-#]` 装饰音、
   `[4-8.3]`/`[4-8.$]` 连音。
8. 时值：`symbol_time = round(60000/bpm)`（**JS `Math.round` 语义**），
   `dur = round(symbol_time × (symbol/type))`，`symbol` 取拍号分母；附点 ×1.5；
   装饰音 = `round(symbol_time/16)`，并从前一个音的时长里扣。
9. 小节 `|` 只作分隔符，不产生时间；连续音符按 `dur` 累加得到 onset，`sustain_ms = dur`。

### 13.4 往返保真度（实测，详见 §13.6）

合成谱与三份真实曲谱（tick / yuanqin / midi）经 `Score → BGI(midi) → Score`：音数一致、
时刻误差 ≤1ms、音高一致率 100%。

### 13.5 已知限制

- 不支持 `keyboard` 类型（网络键盘谱不断言时值，只有 `/` 分隔的相对节奏）。
- `yuanqin` 的连音（`.3/.6/.$`）按"组总时长均分"近似；装饰音（`#`）从前一个音的时长里扣。
  这两种记号在当前曲库里尚未出现，规则待真实样本校准。
- BGI 曲谱里若出现本乐器没有的键（例如社区《卡农》里有 `K`，而风物之诗 21 键里没有），
  解析时照收（交给播放端忽略），**导出时只用本乐器 `key_order` 内的键**。
- 读取 BGI 后文本框显示的是"onset→60fps 帧号"的等价 tick 文本，仅供人看；
  试听用的是解析出的毫秒时间轴，故 31fps 录制的谱面显示帧号会与实际采集帧数不同。

### 13.6 实测校验（2026-10-20）

工具：`tools/compare_sheets.py <A> <B>`（画像 + 往返保真度 + 跨文件比对）。

**转换保真度（各自为基准，`Score → BGI(midi) → Score`）**

| 曲谱 | 格式 | 音数 | 和弦 | 时长 | 时刻误差 | 音高一致率 |
|---|---|---|---|---|---|---|
| 蒲公英的约定（tick） | tick | 1023 | 453（复音≤6） | 3:52 | **max 0.0ms** | 100% |
| 蒲公英的约定（BGI） | yuanqin@66 | 459 | 0（单声部） | 4:14 | **max 0.0ms** | 100% |
| 卡农（BGI 仓库） | midi@120 | 653 | 17（复音≤2） | 2:13 | **max 0.5ms** | 100% |

**yuanqin 时值模型校验**：该曲 70 个 4/4 小节，按本实现累加后平均每小节 3637.4ms（理论 3636ms），

**跨文件比对结论**：这两份《蒲公英的约定》**不是同一编配**，不能逐音比对 ——

## 14. tick 谱面 → BetterGI 两种格式（M2e / M2f）

**规格（用户拍板）**：tick 文本里的数字是**毫秒间隔**（`A1000F` = 按 A 后隔 1000ms 再按 F），
同一份文本导出成两个 BGI 变体，都进「保存文件」左侧下拉：

| 下拉项 | `data` | 文件 `type` | 时间基准 |
|---|---|---|---|
| `tick（YQRec）` | `tick` | —（YQRec JSON） | 毫秒 |
| `BGI · midi` | `bgi_midi` | `midi` | `bpm=125, ticks=480` → **1 tick = 1ms** |
| `BGI · yuanqin` | `bgi_yuanqin` | `yuanqin` | `bpm=300` → 一拍 = 200ms |

> **M2f 变更**：v2 及更早的 tick 记的是"帧间隔"，要靠 `capture.fps` 换算成毫秒 ——
> 掉帧时整首变速，量化到 16.7ms 网格还有 ±8ms 误差。改毫秒后不需要帧率，误差 ≤0.5ms。
> 旧文件靠 `tick.unit` 区分（`"frame"` → 仍按 fps 换算），v1/v2 全部可读。

### 14.1 `type: "midi"`：毫秒直接当 tick

`ms_per_tick = 60000/(125×480) = 1ms`，`onset_ms` 四舍五入成 tick，**量化误差 ≤0.5ms**；
token 末尾的数字就是毫秒数，出问题能逐事件对照。保持时长取 60ms，同键重按留 30ms（`lowest_latency`）。

例：`A1000F250G` → `DA0|UA60|DF940|UF60|DG190|UG60`

### 14.2 `type: "yuanqin"`：把毫秒间隔落成音符时值

`bpm=300` → `round(60000/300) = 200ms` 一拍，于是二分/四分/八分/十六分/三十二分音符 =
400/200/100/50/25ms，配合附点（×1.5）后可用 `[1] [1-*] [2] [2-*] [4] [4-*] [8] [8-*] [16] [16-*] [32] [48] [64]`
把任意毫秒间隔逼近到 **半档以内（≤13ms）**。

| 记号 | 时长 | 记号 | 时长 |
|---|---|---|---|
| `[1]` / `[1-*]` | 800 / 1200ms | `[8]` / `[8-*]` | 100 / 150ms |
| `[2]` / `[2-*]` | 400 / 600ms | `[16]` / `[16-*]` | 50 / 75ms |
| `[4]` / `[4-*]` | 200 / 300ms | `[32]` / `[48]` / `[64]` | 25 / 17 / 13ms |

**编码规则**：

1. 每个音占 `min(到下一个音的间隔, 100ms)`，取**不超过它**的最大时值档（音符时值必须是单个 token）；
2. 剩余空档全部用 `@[n]` 休止补齐，**休止可拆成多个 token**（417ms = `@[1-*]`×5 + `@[1]` + `@[8]`）；
3. **时间轴按绝对时刻推进，并用"解析端会算出的毫秒"累加** —— 按帧/按间隔各自取整都会漂移
   （实测：按帧推进 1023 音漂到 1.9s，按毫秒推进后 ≤13ms 且不累积）；
4. 相邻两个音**有共同键**时，音符时值再减 30ms，强制中间多出一个 `@` 休止：
   BGI 的 `hasCommonChar(本音, 下一 token)` 为真会扣 30ms 提前抬起再补 60ms，净拖慢 30ms；
5. 每满 4 拍补一个 `|`（纯可读性，解析端按 `|` 切分，一个 token 后最多补一个）；
6. 乐器里没有的键直接丢弃（该 token 降级成 `@`），时间轴不变。

例：`A100A100A150A` → `A[12]@[24]A[12]@[24]A[8]@[24]A[8]`（同键连奏各自留 33ms 休止）

### 14.3 实测精度

**tick 文本自身（`Score → 毫秒文本 → Score`）**

| 谱面 | 音数 | 误差 |
|---|---|---|
| 蒲公英 tick 版（1023 音，232s） | 1023 | **max 0.0ms / mean 0.0ms** |
| 合成谱（含前导休止 500ms） | 3 | 0ms（前导休止保留） |

**导出 BGI 后再解析回来**

| 曲目 | midi | yuanqin |
|---|---|---|
| 蒲公英 tick 版（1023 音） | **0.0ms** | max 12.0ms / mean 2.1ms |
| 真实录制 83 音 | 0.0ms | max 10ms / mean 2.8ms |

### 14.4 为什么改毫秒（同一份 1023 音谱面的量化误差）

| 记录方式 | mean | max |
|---|---|---|
| 帧间隔 @60fps | 4.19ms | 8.33ms |
| 帧间隔 @31.49fps（掉帧实测） | 7.99ms | 15.87ms |
| 帧间隔 @144fps | 1.74ms | 3.44ms |
| **毫秒间隔** | **0.00ms** | **0.00ms** |

帧制的误差就是半个帧长（`500/fps` ms），且**采集帧率越低越差**；毫秒制与帧率完全解耦。

## 15. 检测方式切换 / 纵向偏移 / 采样可视化 / 窗口位置（M2o）

用户 4 项需求，一次落地。设计原则：**能进配置的进配置，界面只暴露"必须按场景选"的东西**。

### 15.1 Δ 收进乐器配置，原位置改检测方式下拉

| 项 | M2n 之前 | M2o |
|---|---|---|
| 灵敏度 Δ | 界面滑条（`delta_range` 内手调） | **只有 `detection.default_delta` 一处**，切乐器自动换 |
| 第三行中段控件 | 「灵敏度」+ 滑条 + 数值 | 「检测」+ 下拉（环形 / 小方块）+「偏移」+ 滑条 + 数值 |

```python
# main_window.py
def _delta(self) -> int:
    """灵敏度 Δ 现在固定在乐器 JSON 里（detection.default_delta），界面不再暴露。"""
    return int(self._spec.detection.default_delta)
```

> `delta_range` 保留在 JSON 里只作文档/诊断参考，**代码不再读它做 UI**。新增乐器时只需填 `default_delta`。

### 15.2 两种采样口径的取值

```python
RING_FALLBACK_RATIO = 0.55      # 乐器没标 sample_inner_ratio 时的外环内径

def _effective_inner_ratio(self) -> float:
    if self._sample_mode() != "ring":
        return 0.0                       # 小方块 = 整块 2R 方形（M2m 之前的旧口径）
    ratio = float(self._spec.detection.sample_inner_ratio or 0.0)
    return ratio if ratio > 0 else RING_FALLBACK_RATIO

def _effective_offset_y(self) -> float:
    return float(self._square_offset()) if self._sample_mode() == "square" else 0.0
```

- **环形**：内径取乐器标定值（风物之诗 0.55），没标定就用 0.55；外径固定 0.98R。
- **小方块**：`inner_ratio=0`，等价于 v1.16 之前的整块方形均值（含中心音符图标与四角背景）。
- 两者都经 `CaptureWorker.set_sampler_options(inner_ratio=…, offset_y=…)` 推下去，**参数变化就丢弃缓存的 sampler** 重建（`_ensure_sampler()` 用 worker 自己的选项构造）。

> 换模式 / 挪偏移后基线就作废了（采样的是另一块像素）。UI 不强制清基线，但会在 `_flash_status` 提示"请重新学习基线"。

### 15.3 纵向偏移（`square_offset_y`）

- 滑条范围 `±80`，步长 1，标签显示 `+25px` / `-10px`；**只有小方块模式可用**（`_sync_offset_enabled()`），其他模式灰掉。
- 值语义：**1920 宽基准下的像素**，实际帧按宽度缩放 —— 与 `button_radius` 同一套归一化：

```python
# sampler.py
REF_WIDTH = 1920
def _dy(self) -> float:
    return self.offset_y * self.frame_w / REF_WIDTH
```

`_bounds()` 与 `_make_mask()` 都做 `cy += self._dy()`，保证"取值窗口"与"掩膜"永远同一位置。

> 归一化的理由：同一套配置在 1069 宽截图与 1695 宽截图下，`offset_y=40` 必须是同一个视觉偏移量。
> 测试里要注意：400 宽帧上想移动 40px，得传 `40 * 1920 // 400 = 192`。

### 15.4 学习基线期间的蓝色采样区可视化

```python
# preview.py
SAMPLE_FILL   = QColor(70, 150, 255, 70)      # 半透明蓝
SAMPLE_STROKE = QColor(110, 180, 255, 200)
```

### 15.5 窗口位置记忆（在 M2k 尺寸记忆之上）

| 字段 | 语义 |
|---|---|
| `window_x` / `window_y` | 关闭前的左上角；`-1/-1` = 没记过 |
| `window_width` / `window_height` | M2k 已有 |
| `window_maximized` | 最大化只记标志，不写 `window_x/y` |

```python
def _restore_window_position(self, x, y, width, height) -> None:
    """套用上次的窗口位置；跑到屏幕外（换显示器/拔屏）就拉回主屏居中。"""
    if x < 0 and y < 0:
        return
    visible = any(s.availableGeometry().intersects(QRect(x, y, width, height)) for s in screens)
    if visible:
        self.move(x, y)
    else:  # 屏幕配置变了 → 主屏居中
        ...
```

- `moveEvent` 也走 400ms 防抖（与 `resizeEvent` 共用一个 timer），`closeEvent` 立即落盘。
- 判定用 `intersects`（矩形有交集就算可见），不是"完全在内"—— 允许用户把窗口拖到屏幕边缘一半在外面。

### 15.6 全局采样几何与配置热重载（M2p）

M2o 把"检测方式"和"纵向偏移"做进了界面，但**几何本身**（环多宽、方块多大）还是写死在代码/乐器里。
M2p 把它抽成**全局配置**，并把每个乐器的 Δ 提到仪表盘位置：

```
assets/instruments.json (v3)
├── sampling                     ← 全局：所有乐器共用，改完 1.5s 内生效
│   ├── ring_width_ratio 0.43     环形：0.55R ~ 0.98R
│   └── square_side_ratio 1.0     方块：边长 1R（原 2R）
└── instruments[]
    ├── delta 30                 ← 每个乐器自己的灵敏度
    └── detection { metric, channels, refs, note }
```

数据流（谁用这两个值）：

```
instruments.load_sampling()  ──►  MainWindow._sampling
                                    │
      _effective_inner_ratio() ─────┤ ring → sampling.ring_inner_ratio(0.98−width)
      _effective_square_side() ─────┤ square → sampling.square_side_ratio
                                    ▼
                    CaptureWorker.set_sampler_options(inner_ratio, square_side, offset_y)
                                    │
                                    ▼
              KeySampler(inner_ratio=…, square_side=…, offset_y=…)  ← 几何只在这里落地
```

- **`square_side` 的语义是"边长 × R"**（`_half_extent = r * square_side / 2`）。
  用户反馈"检测区域太大"后从 `2.0` 改到 `1.0`，面积降到原来的 1/4。
- **环形模式下 `square_side` 完全无效**（有单测锁住）：环形靠掩膜裁，ROI 仍是 ±R。
- **按需重读（M2q.2，取代 M2p 的 1.5s 轮询）**：`_JSON_CACHE` 仍用 `(mtime_ns, size)` 做签名，
  `instruments_mtime()` 只用来判断"变没变"。`_reload_instruments(source=, manual=)` 做四件事：
  换 `_sampling` / 重解析当前乐器（Δ 可能改了）/ `_sync_sampler_options()` / 状态栏提示。
  **读坏了只 warning，不改变现有参数**（编辑器存盘到一半时不能崩）。
- 触发点只有四个：**启动**（一次）、**开始预览**、**学习基线**、**F5**（手动，且会明确回"没有变化"）。
  运行期没有任何后台轮询。

> **为什么去掉轮询**：实测 `os.stat(mtime_ns)` 约 **2.8µs/次**，1.5s 一次折合单核 **0.0002%** ——
> 性能上本来就可以忽略。真正的收益是**行为确定**：录制途中不会突然弹"配置已重载"
> （判据/采样在录制中途变化会让同一份谱子前后口径不一致），也不会读到写了一半的文件。
> 调参体验由 F5 + "开预览/学基线自动比对" 兜住。

## 16. 分段点采样 + 加权判据（M2q / v1.20）

**一句话**：不再把"整块/整环"像素求均值，而是沿键帽一圈取固定个数的**基准点**；
判据也从"看最大跌幅"换成"按按下时的颜色变化方向做加权投影"。

### 16.1 采样（`vision/pointsampler.py::KeyPointSampler`）

| 模式 | 基准点 | 起点 | 点数 | 默认半径 |
|---|---|---|---|---|
| 环形 | 内环圆周（半径 = `ring_inner_ratio·R`） | 内环**正上方**切点 | `sampling.ring_points`（默认 8） | **0.80R**（`ring_width_ratio 0.18`） |
| 方块 | 四条边（边长 `square_side_ratio·R`，恒居中） | **左上角**，顺时针 | `4 × sampling.square_points`（默认 4/边 = 16 点） | **0.55R**（半边长；`square_side_ratio 1.1`） |

每个基准点取其周围 `point_patch_ratio·R`（默认 0.06R，至少 1px）圆斑的均值，
再对这圈点求平均 → 每键一个 RGB。接口与 `KeySampler` 对齐（`sample()` 返回 `(K,3)`）。

- 越界点直接裁掉（不 clamp），整键无有效点时返回 `(0,0,0)`；
- 帧尺寸变化要重建（与 `KeySampler` 同约定）；
- 几何全部来自 `instruments.json` 的 `sampling` 段，界面「半径」滑条改的就是它。

### 16.2 判据（`KeyThreshold.mode="weighted"`）

```
score = Σ_c w_c · max(0, (base_c − cur_c) − tolerance) / Σ_c w_c        # 判按下：score ≥ Δ
```

- **只算变暗方向**：`max(0, …)`，背景变亮不会误判；
- **权重** `w_c` 来自 `detection.weights`（可手写），缺省时由 refs 的跌幅归一化
  `w ∝ max(0, unpressed_ref_c − pressed_ref_c)`；两者都缺 → 等权（= 三通道平均跌幅）；
- **死区** `detection.tolerance`（默认 8 灰阶）：单通道变化不到死区贡献 0，
  用来吃掉各键基准色偏差与压缩噪声；
- 除以 `Σ w_c` 让 score 保持"灰阶"量级，Δ 与 `max_drop` 基本可比
  （同一次按下略小于 `max_drop`，因为它是对参考方向的最优投影）。

### 16.3 逐键基线（v1.20 起，判按的默认基准）

`PressDetector(spec, thresholds, baseline=(K,3))` 会给**每个键**替换阈值的 `base_*`。

> **为什么必须逐键**：`thresholds_from_baseline()` 里的 `base_*` 是 area 内各键基线的
> **均值**。风物之诗的键帽半透明，角色身体把中列两个键压暗了 57 灰阶 —— 用区域均值时
> 这两个键会**一直判成按下**；逐键基线天然抵消这种空间差异。
> 配置档新增 `baseline` 段保存它，旧配置档没有该段则退回区域均值。

`keys_panel` 的实时数值也走同一套逐键阈值，保证"看到的数 = 判定用的数"。

### 16.4 半径滑条（取代 M2o 的偏移滑条）

| 模式 | 滑条含义 | 量程 | 默认 | 写入字段 |
|---|---|---|---|---|
| 环形 | **内环半径**（点所在的圆周） | 0.20R ~ 0.95R | **0.80R** | `ring_width_ratio = 0.98 − 内环半径` |
| 方块 | **中心到四边的距离**（= 半边长） | 0.20R ~ 1.50R | **0.55R** | `square_side_ratio = 2 × 该值` |

- 拖动即时生效（内存），松手/400ms 防抖后 `instruments.update_sampling()` 写盘；
- 写盘是**文本级**替换 `"ring_width_ratio": x`，保留注释与排版，不做整份 `json.dump`；
- 启动时 `_restore_ui_options()` 直接读 `instruments.json` 里的值当初始值；
- 打包后写的是 `dist/YQRec/_internal/assets/instruments.json`（`YQREC_ASSETS`）。

### 16.5 采样点的显示（M2q.3 起**常显**）

`PreviewWidget.set_sampling(inner_ratio=, square_side=, ring_points=, square_points=)`：

- 检测圈一画出来就带**小红点**（`POINT_DOT_COLOR` = RGB(255,72,72, alpha 235)，
  半径 `max(1.8, 0.09R)`），不再只在学基线时出现；
- 点位置用 `base_points()` 现算，**与 `KeyPointSampler` 同一函数** → "看到的点 = 采样的点"；
- 注意点的半径用**真实 `KeyPoint.r`**，而圈是按 `MARKER_SCALE=1.6` 放大画的（圈只为看清边界）；
- 主窗 `_sync_preview_sampling()` 在「半径」滑条拖动、「检测」下拉切换、配置重读、
  启动恢复时都会推一次 → **点随滑条实时移动**；
- `show_sample_overlay(point_mode="points")`（学基线时）现在只加一条极淡的参考圆
  （alpha 55），红点仍由 `_paint_grid` 常显；学完 `clear_sample_overlay()` 只清参考圆。
- `set_sampling(show_points=False)` 可整体关掉红点（测试/截图用）。

按下时的绿圈：填充 alpha **42**（`PRESSED_FILL_ALPHA`）、描边 alpha 190、线宽 1.8 —— 值调低是
用户要求（"能更好看清捕获画面"），改它只需要动 `preview.py` 顶部常量。

> 坑：`QT_QPA_PLATFORM=offscreen` 下字体库为空（`QFontDatabase.families() == []`），
> `grab()` 出的图所有文字都是豆腐块。**验证界面文字必须用默认平台**（`QWidget.grab()` 不需要 show）。

### 16.6 验收阈值（真图实测，用于防止口径被放松）

| 用例 | 环形 0.80R×8 | 方块 0.55R×4 | Δ |
|---|---|---|---|
| 风物之诗 / 红树 1069×598（`-7`） | 59.2 / 噪声 1.5 | 60.4 / 0.0 | 30 |
| 风物之诗 / 花海 1695×956（`+3 1 2 5`） | **39.4 / 0.0** | 38.1 / 6.1 | 30 |
| 谐律键琴 / 1696×957（`+2 7`） | 47.2 / 0.0 | 48.2 / 1.0 | 40 |

> 对比旧口径（环带 0.55R×16 / 方块 0.50R×8）：风物之诗花海 33.3/5.6 → **39.4/0.0**，
> 红树 53.2/0.7 → 59.2/1.5，谐律键琴 44.2/2.0 → 47.2/0.0 —— 信号更高、干扰更低。
> 点数从 16/8 减半到 8/4 后得分几乎不变（±1），所以采样开销也降了一半。
>
> 反之把环形半径继续往下调（0.40R）会掉到 3~5 直接漏报；往上超过 0.9R 会踩到键帽描边。
> 改半径后必须重新学基线并看灯。

## 17. 首次运行建档与打包日志（M3f / 契约 v1.34）

### 17.1 首次运行 pre-show 建档（关掉「标题栏 X 置灰」的根源）

**症状**：打包 exe 首次运行（`%APPDATA%\YQ_moTools` 不存在）时标题栏关闭按钮偶发禁用。
**机制**：Windows 把 X 置灰的唯一途径是 ghost 窗口（窗口可见后主线程消息队列停摆 >5s）。
代码里唯一一处「只在首次运行发生、且发生在窗口可见之后」的主线程写盘是：

```
_restore_window_size() 置 _ui_ready=True
→ _apply_on_top_state() 的 setGeometry() 触发 moveEvent/resizeEvent
→ 400ms 防抖（show() 后 ~0.4s 触发）
→ _persist_window_size() → mkdir %APPDATA%\YQ_moTools + 新建 settings.json
```

老用户值没变 `_persist_window_size` 直接跳过，所以只有首次运行有这次建档；在杀软实时
扫描 / 受控文件夹访问 / 漫游配置档的机器上，新建文件可卡主线程数秒 → ghost → X 置灰。

**修法（`main_window.py::MainWindow.__init__` 末尾）**：

```python
if not config_path().exists():
    self._save_app_config()   # 构造期（show() 之前）建好 settings.json
```

此后防抖落盘因「值没变」不再写。新增涉及启动写盘的代码时同理：**必须在 `show()` 之前**。

**验证工具**：`out/probe_close_button.py`（Win32 探针：`IsHungAppWindow` + `GWL_STYLE` +
SC_CLOSE 菜单项状态），可发给报告者在复现机器上跑；`hung=True` 即证实 ghost 机制。

### 17.2 打包 exe 的日志初始化（frozen 入口禁止相对导入）

`app.py` 既是 `python -m yqrec.app` 的入口，也是 PyInstaller 的打包脚本（spec `Analysis`
入口）。frozen 下它以 `__main__`（**无父包**）运行，任何相对导入都会 `ImportError`。
曾因此导致打包版文件日志**从未装上**：`_log_dir()` 里 `from .config import DATA_DIR_NAME`
抛 ImportError → 被 `run_gui()` 的 `except Exception` 静默吞掉退回仅控制台（真实机器
`%APPDATA%\YQ_moTools` 有 settings.json 却没有 `logs/` 目录即铁证）。

规矩与现状：

- `app.py`（含 `run_gui` 调用链）内**只用绝对导入**（`from yqrec.config import …`）；
- `run_gui()` 的日志初始化失败不再完全不可见：异常 traceback 留档 `%TEMP%\yqrec_log_fail.txt`；
- `cli.main()` 对 `gui` 子命令**跳过**无目录的 `setup_logging()`（否则全局 `_configured`
  被置位，`run_gui` 里幂等跳过 → 文件 handler 永远装不上）；文件日志统一由 `run_gui()`
  用真实日志目录初始化。

排障口诀：打包版没日志 → 先看 `%TEMP%\yqrec_log_fail.txt`；源码路径没日志 → 别在
`cli.main()` 里抢跑 `setup_logging()`。
