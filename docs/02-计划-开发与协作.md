## 1. 迭代路线与阶段成果

> **敏捷迭代**（2026-10-20 用户拍板，替代原 P0→P6 瀑布计划）：每轮先交出可双击运行的 exe → 用户实机跑 → 按反馈迭代；单测/ruff 只作回归护栏，不作阶段门禁。
> **本节只回答「每个阶段实现了什么」**。逐轮细节（用户原话、根因与踩坑）随 M0–M4 记录于 2026-10-26 归档，可在 git 历史中查到；接口细节见 [03](03-实现规格与接口契约.md)（含附录 A 契约明细）。

### 1.1 迭代原则（铁律）

1. **每轮必须出 exe**（`dist/YQ_moTools/YQ_moTools.exe`）；只有单测通过 = 没交付。
2. 每轮只做一个**用户可感知的能力**；范围宁小勿大，做不完就砍。
3. **验收 = 用户实机用起来 + 反馈清单**；单测只保护已交付的纯逻辑，不堆虚拟测试。
4. 捕获后端与判定参数「能用即可」，阈值在实机反馈里调，不在空环境反复论证。
5. 契约只做加法；必须破坏性变更时升版本 + 写迁移 + 广播。
6. 每轮收口必须能回答：**用户这次比上次多能做什么？**

#### M6g · 注入对齐 BGI + 启动自提权（2026-10-29）

- **根因**（读 BGI 源码逐行对照后确认）：原神 PC 端从米哈游启动器继承**管理员令牌**，普通权限进程的 `SendInput`/`PostMessage` 被 UIPI **静默丢弃**（返回值成功、`GetLastError` 为 0）。BGI 的解法是 `RuntimeHelper.EnsureElevated` → `Process.Start(Verb="runas")` 每次启动把自己换成高权限实例（README FAQ：「因为游戏是以管理员权限启动的」）。
- **自提权**：新增 `yqrec/elevate.py`；`run_gui()` 第一件事就是 `ensure_admin()`，成功拉起高权限实例后原进程直接退出。三条边界：只对打包版生效（源码运行 `sys.executable` 是解释器，重启只会丢参数）；`YQREC_ELEVATE_TRIED` 防循环；拒绝 UAC（返回 5 / 1223）继续以普通权限跑，只在消息区提示后果。`YQREC_NO_ELEVATE=1` 可关闭。
- **键事件双填**：`inputsim._key_input()` 改为 **`wVk` + `wScan` 同时填**（同 BGI `InputBuilder`），不再用 `wVk=0` + `KEYEVENTF_SCANCODE` 只发扫描码 —— 后者要按当前键盘布局反查虚拟键，且 `GetKeyState(VK)` 查不到按下态；`press_space()` 默认也跟着改（扫描码仍随事件带上，"只认扫描码"的环境可用 `use_scan_code=True` 兜底）。
- **失败可见化**：BGI 的 SendInput 封装是「失败即抛异常」。我们注入在自己的线程里跑，改为 `KeyPlayer` 累计 `KEY_FAIL_STREAK_LIMIT`（5）次「能发却发不出去」后 `_interrupt()`，状态栏给出「目标程序可能以管理员权限运行」；偶发一次失败不中断。
- **启动诊断**：`_report_paths()` 增加「权限」一行（管理员 / 普通用户 + 原因），写进 `data\logs\yqrec.log`；提权发生在日志系统之前，结论同时落一行到 `%TEMP%\yqrec_elevate.log`（否则「双击没反应」无从查起）。
- **存档目录粘性**：提权会让 `%APPDATA%` 从「写不进」变成「能写」，数据目录可能从 `<exe>\data` 跳回 AppData，表现就是「标定档没了、窗口大小回默认」。`_sticky_data_dir()` 加一条窄规则：主目录**空**而备选目录**已有存档**时继续用旧的。

#### M6i · 去掉前后台按钮，通道改全局参数（2026-10-29）

- **用户要求**：演奏模式里的「前台/后台」按钮去掉，改由 `assets/instruments.json` 的全局 int 参数控制，默认后台；通道取值也不再写进 C 盘存档。
- **参数**：`key_play_channel`（int，所有乐器共用）：`0` = 后台 `PostMessage`（默认）/ `1` = 前台 `SendInput`；`instruments.load_key_play_channel()` 缺项/非整数/越界回落 `0` 并 warning，绝不抛。
- **UI**：删掉演奏控制条里的 `_btn_key_mode` 胶囊、`_make_key_mode_button()`、`_switch_key_mode()`、`_sync_key_mode_button()`，以及 QSS 的 `#KeyMode` 规则；入口 tooltip 改为显示当前通道 + 参数名（"通道由 instruments.json 的 key_play_channel 决定"）。
- **生效时机**：启动 / F5 / 配置重读时刷新 `MainWindow._key_play_channel`，`_make_key_sink()` 只读缓存 —— 演奏途中改 JSON 只记日志/提示，**下一次点「演奏」生效**（换通道要重建时间轴，不做热切）。
- **存档**：`UiConfig.key_play_mode` 字段删除，`CONFIG_VERSION` 5 → 6，`_migrate` 把旧档里的 `ui.key_play_mode` 摘掉（避免"看起来还在生效"的残留键）；`settings.json` 不再出现前后台数据。
- **测试**：删掉胶囊相关用例，新增 `load_key_play_channel()` 取值/兜底、全局参数→`_make_key_sink()` 链路、旧键迁移清理三类用例。

## 9. 验收指标与质量门

### 9.1 指标

| 类别 | 指标 |
|---|---|
| 识别 | 单音 F1 ≥0.98；和弦 ≥0.95；onset MAE ≤20ms（p95 ≤40ms） |
| **视频源（浏览器）识别** | **F1 ≥0.90**（与源谱比对）；受保护内容能明确报"无法识别"而非静默出错 |
| 捕获 | ≥55fps、丢帧 <2%、后端自动降级可恢复；屏幕区域与窗口两模式均可用 |
| 16:9 | 720p/1080p/1440p 共用一套标定，检出率差异 <5% |
| 数据链路 | 单帧处理 p95 <8ms；**零编码零落盘**；L1 <1MB/3min；30min 无磁盘突增 |
| 播放 | 与事件表理论时间偏差 p95 ≤15ms；0.5–2.0x 不错位；循环/定位正确 |
| 编辑器 | 3000 字符无卡顿；错误定位到行；高亮跟随 |
| 导出 tick | 23 首已知谱 解析→序列化→再解析 **文本一致**；现有 tick 工具可正常播放 |
| 导出 BGI | `bgi_sim.js` 事件序列与源 Score 一致（onset 误差 ≤1ms、键序一致）；`manifest.json` 结构合法 |
| 稳定性 | 连续录制 30 分钟不崩、内存增长 <50MB |


判定：以上三条 + **用户实机跑 ≥1 次并给出反馈清单**。有反馈即迭代有效；不要求零缺陷、不要求覆盖率、不要求 P0 数据齐全。

> 原则：**能跑的 exe 优先于漂亮的指标**。指标（§9.1）保留为长期质量目标，随迭代达成，不再作为进入下一阶段的前提。

## 10. 沟通协议

- **每完成一个任务**，向 Lead 发**三行报告**：
  ```
  ① 做了什么：<一句话>
  ② 证据：<测试命令 + 结果摘要 / bench 数字>
  ③ 风险/待办：<阻塞点 或 下一步建议>
  ```
- **阻塞立即报**：不自行扩大范围、不改契约、不改别人目录。
- **禁止**：伪造测试结果、删除他人测试、`git commit`（见 §11）、引入未批准依赖、修改 `assets/**`。
- **Lead 每轮**：`team_task_list` → 派活（`send_message`）→ `wait_agent` → 评审 → 集成 → 下一批。

## 11. 版本管理（共享文件系统约定）

- 单仓库、单工作树（成员共享文件系统，**不做多分支**）；
- **只有 Lead 执行 `git commit` / `git tag`**（避免 index.lock 竞争）；成员只跑 `git status/diff`（只读）；
- Lead 在里程碑提交，message 形如 `[M2] P1 引擎: capture+vision+timeline+cli`；
- 归档点：M0 契约冻结、P0 结论、P1 CLI、P3 编辑器、P4 闭环、P6 发布。

## 文档更新规则（跨 Agent 协作）

| 场景 | 谁改 | 改哪份 | 要求 |
|---|---|---|---|
| 产品/架构决策变更 | Lead | **01** | 附决策记录（日期 + 原因 + 影响范围） |
| 接口契约变更 | 契约 owner + Lead 批准 | 01 §5 相关节 + 03 附录 A | 同步实现/测试，广播受影响 owner（提交信息写明） |
| 里程碑/排期/人员/任务调整 | Lead | **02** | 同步任务板；写作用域变更须先广播 |
| 任务级进度 | 任何人 | **写入任务板**（team_task_*） | **不要把进度写进文档**，文档只放稳定信息 |
| 技术结论（如 P0 数据） | 该实验 owner | 02 §7 记录表 + 01 §6.2 判定 | 必须附命令与数字 |
| 曲谱格式（tick / BGI）语法变更 | 格式 owner | **07** + 03 §7/§8 | `07` 是给 Agent/外部工具的速查，改了要同步实测表与反例 |

> 原则：**文档 = 稳定契约与知识；任务板 = 动态状态**。两者不混。
