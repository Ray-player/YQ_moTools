## 4. 关键设计决定（改之前先读理由）

| # | 决定 | 理由 |
|---|---|---|
| D1 | **GUI 录制挂在 `CaptureWorker`，不接 `Session`** | `Session` 自带捕获后端 + 分析线程；与预览线程并列会对同一区域开两份捕获、两份采样，违反"分析线程唯一"。`Session` 只服务 CLI/回归 |
| D2 | **谱面单一数据源 = `tick.text`**（JSON 里没有 `events[]`） | 用户明确要求去冗余。`capture` 块不是谱面，是**帧→毫秒换算参数**（仅 v2 及更早的 `unit:"frame"` 用）；`instrument` 用于键→音名→音频 |
| D3 | **tick 文本的间隔单位是毫秒**（`A1000F` = 按 A 后隔 1000ms 再按 F） | M2f 用户拍板。帧间隔要换算、掉帧就变速，量化误差是半个帧长（60fps 8.3ms / 31.5fps 15.9ms）；毫秒制误差 ≤0.5ms 且与帧率解耦 |
| D4 | **试听经 `PlaybackController` 桥接** | `Player` 在后台线程回调 `on_note/on_state`，必须经 Qt Signal 回主线程才能碰控件 |
| D5 | **单击判定必须按乐器选判据**，Δ 写在乐器 JSON | `max_drop` 只对**不透明**键帽成立；半透明键帽（风物之诗）背景越亮绝对跌幅越小，一个 Δ 覆盖不了两景，必须用 `chroma` 相对色偏。Δ 交给配置而非滑条，避免用户调坏后误判"识别坏了" |
| D6 | **采样口径 = 外环优先**，方块模式留作兜底 | 键帽中心有游戏音符，按下时几乎不变，留在均值里只稀释信号。外环信噪比 27~55 倍 vs 整块方形 4~12 倍。方块模式保留是因为个别乐器/分辨率下外环可能被键帽描边污染，此时可退回整块并用偏移微调 |
| D7 | **纵向偏移按 1920 宽归一化存盘** | 与 `button_radius` 同一套口径：同一份配置在 1069 / 1695 / 1920 宽画面上是同一个视觉位移 |
| D8 | **采样几何全局化、Δ 按乐器** | 几何（环多宽、方块多大）决定「采哪块像素」，与乐器无关，放全局最省心；Δ 依赖键帽材质与背景，必须按乐器。分层后调几何一处改完 6 个乐器都受益，调灵敏度又不会互相牵连 |
| D9 | **配置热重载用 mtime 轮询，不用 QFileSystemWatcher** | Windows 编辑器「写临时文件再改名」会让 watcher 收到多次甚至丢失事件；`stat` + `(mtime,size)` 签名更可靠，1.5s 一次开销可忽略 |

数据流（录制链）：

```
CaptureWorker(采样+判按) ─录制中─► RecordingBuffer(帧 ts + PressEvent)
      │ 停止                                │ finish()
      ▼                                     ▼
 assemble() ──► Score ──► tick_text ──► 文本框 / JSON（tick.text）
                              │
                              └── tick_spans() ──► 试听高亮（token 字符区间）
```

采样口径的取舍：

```
画面帧 ──► KeySampler(inner_ratio, offset_y)
              │  ring:  只统计 0.55R ~ 0.98R 的圆环（跳过中心音符）
              │  square: 整块 2R 方形（含中心 + 四角背景），可整体上下平移
              ▼
           (K,3) RGB 均值 ──► thresholds_from_baseline ──► PressDetector(max_drop / chroma)
```

## 5. 数据与配置契约

### 5.1 谱面 JSON（`version: 3`，`format: "yqrec.recording"`）

```jsonc
{
  "version": 3, "format": "yqrec.recording", "score_format": "tick",
  "name": "谱面_tick_20261020_174428",
  "created_at": "2026-10-20T17:44:34+08:00",
  "instrument": { "id": "fwzs", "name": "风物之诗", "key_count": 21 },
  "capture": { "backend": "gdi", "fps": 31.49, "frames": 1005, "duration_ms": 31882.2 },
  "tick": { "unit": "ms", "text": "D14G13Q13E9F2H2V1E12A14..." }
}
```

- **v3 起 `tick.unit="ms"`**：`capture` 块只作记录，不再参与换算。
- **v1/v2 旧文件**（`unit:"frame"` 或没有 `unit`）仍可读：`record_unit()` 返回 `frame`，
  `score_from_record()` 按 `ms_per_frame()`（优先 `duration_ms/(frames-1)`，其次 `1000/fps`，否则 60fps）换算。
- v1 的 `events[]` 被忽略 —— 谱面本来就在 `tick.text`。

### 5.2 应用设置 `%APPDATA%\YQRec\settings.json`

```jsonc
{
  "version": 1, "backend": "auto", "profile": "default", "target": null,
  "record": { "hotkey": "F9", "chord_window_ms": 25.0, ... },
  "audio":  { "enabled": true, "volume": 0.8, "offset_ms": 0 },
  "ui": {
    "language": "zh-CN", "theme": "dark", "hud": true,
    "always_on_top": true,                       // M2b 置顶
    "window_width": 660, "window_height": 980,   // M2k 尺寸
    "window_maximized": false,
    "window_x": 120, "window_y": 88,             // M2o 位置（-1 = 没记过）
    "sample_mode": "ring",                       // M2o ring | square
    "square_offset_y": 0                         // M2o 1920 宽基准像素
  },
  "paths":  { "last_score_dir": "D:\\谱面" }
}
```

> 子配置都是 `slots=True` 的 dataclass，序列化**必须** `dataclasses.asdict`（`vars()` 会抛 `TypeError`）。
> `load_config()` 的**段合并列表**要包含所有段（`ui/target/record/audio/paths`），漏一个就是"写进去读不回来"。

### 5.3 标定档 `%APPDATA%\YQRec\profiles\default.json`

M1 起就有：区域 + 21 个键位 + 阈值/Δ + 乐器，启动自动恢复（**不含基线**，基线必须每次学习）。

## 6. 踩过的坑（别重踩）

1. **打包前必须确认 `YQRec.exe` 没在运行**：旧进程锁住 `dist/YQRec` 的 exe/dll，PyInstaller 的 COLLECT rmtree 又会被 safe-delete 拦，结果 dist 只剩半套。
2. **可靠打包流程**：
   ```bash
   .venv/Scripts/python.exe -m PyInstaller --noconfirm \
       --distpath "$TEMP/yqrec_new" --workpath build/work_new build/yqrec.spec
   cp -a "$TEMP/yqrec_new/YQRec/." dist/YQRec/     # 覆盖 .exe/.dll 需 sandbox 关闭，否则 EBUSY
   ```
3. **音频路径曾全错**：`note_to_audio` 写成 `audio/YuanShen/<inst>/x.mp3`，实际文件在 `assets/audio/<inst>/`。已统一改为 `audio/<inst>/x.mp3`；新增乐器/音频时按此规则。
4. **`pygame` 不能进 `EXCLUDES`**，且 datas 必须带 `assets/audio`，否则 exe 能启动但**完全静音**（只在日志里刷"缺少采样"）。
5. **`Player.on_note` 给的是 `Score.events` 下标（含 RestEvent）**，而 tick token 只数和弦 → 必须换算（`PlaybackController._ordinal_of_event`），否则高亮会跳到第 2、4、6 个音。
6. **`slots=True` dataclass 不能用 `vars()`**：`AppConfig.to_dict` 用 `asdict`。
7. **`git add -A` 会吃掉用户的谱面 JSON**：已在 `.gitignore` 加 `谱面_*.json`。
8. **改窗口标志（置顶）会隐藏窗口**：`setWindowFlags` 后要 `setGeometry(旧几何)` + 可见时 `show()`。
9. **BGI 曲谱 token 的方向别搞反**：`[D|U]<keys><n>` 的数字是"**本事件之前**先等 n tick"
   （`main.js` 里 sleep 在 keyDown/keyUp 之前）。按"之后"解释会让所有音符偏移一个间隔。
   实测判据：按"之前"解释，真实《卡农》的键保持时长为 153–1580ms；按"之后"解释会出现 18 个 0ms 保持。
10. **导出 BGI 的保持时长只能按"同键"裁剪**：按和弦裁剪会把外部曲谱的双声部压成单声部（往返失真）。
11. **新增判据要改两处入口**（M2n 血案）：`KeyThreshold.accepts()`（校验/测试）与
    `PressDetector._signals()`（实时判定）。只改前者 → 状态机里该 metric 掉进单通道分支、
    `_limits()` 返回 None → 每帧被 `continue` 跳过，现象是"学完基线怎么调 Δ 都不亮"。UI 的 Δ 显示也要同口径。
12. **预警信号**：如果某个判据在**所有** Δ 下都不触发，别怀疑参数，先查分派。
    可以用 `vision/thresholds.chroma_axis()` 之类诊断函数打印实际取到的信号值。
13. **`KeyPoint.r` 是比值不是像素**（`button_radius / 1920`）。画圈/取 ROI 一律 `r * frame_w`。
    M2o 写浮层截图脚本时传了像素值，结果蓝色方块铺满整个预览窗——代码没错，是调用方单位错。
14. **两处 `offset_y` 单位不同是有意的**：`KeySampler.offset_y` 收 **1920 基准值**（自己按 `frame_w/1920` 缩放），
    `PreviewWidget.show_sample_overlay(offset_y=…)` 收**帧像素**（渲染层只管画）。换算只在
    `main_window._show_sample_overlay()` 里做一次。改这里时别"统一"成一种，会让另一侧错位。
15. **`square_side` 是「边长 × R」而不是半边长**：`_half_extent = r * square_side / 2`。
    写成半边长会让框大出一倍（M2p 改这个值时就差一点反了）。环形模式下它完全无效（有单测锁住）。
16. **配置缓存签名要带 size**：同一毫秒内两次写盘可能拿到相同 mtime，只比 mtime 会读到旧值。
17. **学基线必须全松开**：用按下态画面学基线 → 基线本身就偏高 → 之后按下去也检不到。
    M2n 加了"可疑基线"提示（某键色偏与中位数差 > 20 就警告），但它只是提示，**不会自动修**。

## 7. 已知限制（不是 bug，别当 bug 改）

| 限制 | 说明 | 去向 |
|---|---|---|
| 读取后不能"另存" | 「保存文件」保存的是**文本框里的内容**（不管是录制/读取/手输），但格式转换只从 tick 出发 | M3 编辑器一起做 |
| 无变速/定位 | 试听固定 1.0x、从头播 | M3（`Player` 已支持 `set_speed/seek`，只差 UI） |
| 置顶窗可能挡住框选视线 | 框选遮罩本身也置顶且抢焦点，拖拽不受影响 | 若用户反馈碍事，再让框选期间临时隐藏主窗 |
| 预览窗与识别区域重叠会"自拍" | 截屏会把 YQRec 自己拍进去 | 用户自行摆位；M5 可加"区域与窗口相交检测"提示 |
| 采集帧率可能只有 ~31fps | gdi + 预览开销所致；tick 已改毫秒，节奏不受影响，但快音符仍可能漏判 | M3 调 `PREVIEW_EVERY`/采样策略 |
| 无热键 | 用户明确不要（避免与游戏按键冲突） | — |
| BGI `keyboard` 类型不支持 | `midi` / `yuanqin` 已双向，`keyboard` 是另一套键位映射 | 需要时再评估 |
| 换检测方式/挪偏移后基线作废 | 采的是另一块像素，必须重学基线 | UI 只提示，不自动清（自动清会让用户以为丢配置） |
| 环形模式对小键位可能被描边污染 | 外径固定 0.98R，键帽有粗描边时环带会包含描边 | 此时切「小方块」+ 偏移微调 |
| `refs` 是按环形口径标定的 | 切到小方块后均值会变（含中心图标与四角背景），Δ 未必仍最优 | 用「学习基线」贴合；必要时改该乐器的 `delta` |
| jhzq / ljdsq / ykq / yy 的 Δ 仍是占位值 40 | 没实机截图标定过 | 拿到截图后按 §5.1 的流程回填 |
