## 2. 一分钟摘要

- **是什么**：框一块屏幕区域 → 你在游戏里弹 → 逐帧判键 → 生成谱子 → 编辑器试听微调 → 导出 tick 谱 / BetterGI JS 脚本。
- **当前进度（2026-10-22，M3 收口）**：UI 按设计包重做（日/夜双主题、四档按钮、三段卡片、试听胶囊、状态栏拆徽标/消息）→ 产物与数据目录改名 `YQ_moTools` → **新增 `j-HDR` 截图后端并设为默认**（HDR 屏唯一颜色正确的路径；`hdrcapture` 取 FP16 + 按每屏 SDR 白电平归一，SDR 下与 GDI 逐像素一致）→ 截图方式写入 `settings.json` 记住 → 回退链 `hdr → dxgi → gdi` → 修首次运行关闭按钮置灰（ghost 窗口）与打包版文件日志坑 → **新增键鼠输入注入 `record_click`（int：0 关 / 1 激活窗口+空格 / 2 鼠标点击）**。`dist/YQ_moTools/YQ_moTools.exe` 200MB，**415 项测试全绿**，契约 **v1.34+**。
  阶段成果与已知限制见 [02 §1.5](02-计划-开发与协作.md) 与 [M3-完成记录](M3-完成记录.md)；**要给 UI 提改造方案，直接看 01 §13（UI 设计规范）**。
- **识别源不限于游戏**：任意屏幕区域都行——原神窗口、**浏览器里播放的原神演奏视频**、本地播放器、直播画面。默认目标是"屏幕区域"（DXGI 抓任意子矩形），"窗口模式"（WGC）用于排除自身悬浮窗遮挡。
- **核心链路**：逐帧截取 → **内存**分析 → 只存 21 键 RGB 时序（**不录视频、不落盘图片**，≈0.26 MB/分钟）。
- **捕获方案**：`j-HDR / DXGI / GDI / WGC / PrintWindow` 五后端，按目标类型路由 + 回退链 + 失败提示；**屏幕区域 → j-HDR（默认，HDR 下也正确）→ DXGI → GDI，窗口 → WGC**。
- **一期范围**：无延音 5 乐器 + 识谱 + 播放器 + 编辑器 + 双格式导出 + 打包；二期补延音/14 键/MIDI 预览。
- **工期**：单人 29–38 人天；6 成员并行后 wall-clock 约 2.5–4 周。
- **最大未知**：G2「按下=变暗」的真实信噪比 → P0 第一件事（见 01 §3.1、02 §7）。

## 3. 文档更新规则（跨 Agent 协作）

| 场景 | 谁改 | 改哪份 | 要求 |
|---|---|---|---|
| 产品/架构决策变更 | Lead | **01** | 附决策记录（日期 + 原因 + 影响范围） |
| 接口契约变更 | 契约 owner + Lead 批准 | 01 §6 相关节 + `docs/CONTRACTS.md` | 契约升版本号并广播 |
| 里程碑/排期/人员/任务调整 | Lead | **02** | 同步任务板；写作用域变更须先广播 |
| 任务级进度 | 任何人 | **写入任务板**（team_task_*） | **不要把进度写进文档**，文档只放稳定信息 |
| 技术结论（如 P0 数据） | 该实验 owner | 02 §7 记录表 + 01 §3.1 判定 | 必须附命令与数字 |

> 原则：**文档 = 稳定契约与知识；任务板 = 动态状态**。两者不混。
