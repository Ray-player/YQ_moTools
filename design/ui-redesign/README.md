## 2. 文件结构

```
design/ui-redesign/
├── README.md                  ← 你在这里（索引 + 决策速览）
├── tokens.json                机器可读令牌（主题 + 叠加层 + 几何 + 对比度实测）
│                              给工具/其他 Agent 读；人读 02
├── docs/
│   ├── 01-设计规范.md          风格定义（5 条硬规则）、信息层级模型、双主题策略、
│   │                          对现有 11 条视觉问题的处置、反例清单
│   ├── 02-设计令牌.md          夜/日并排色板、字体、几何、焦点态、对比度实测
│   ├── 03-界面规格.md          逐个控件：尺寸 / objectName / 文案 / 状态 / 两主题表现
│   └── 04-实施指南.md          ★ 代码地图 + 10 步落地 + 验收清单 + 禁区 + Qt QSS 坑
├── templates/                 ★ 可直接拷进 src/yqrec/ui/ 的代码
│   ├── theme.py               令牌表（唯一颜色来源）+ apply() + 图标配色 + 下拉箭头生成
│   └── qss.py                 唯一 QSS 模板（{{token}} 占位，两主题共用几何）
└── preview/
    └── index.html             可交互视觉基准（5 运行态 × 2 主题 + 组件标本 + 令牌表）
```

**为什么只有两个 `.py`**：配色与样式耦合最紧，拆成 `theme.py`（颜色）+ `qss.py`（样式）两层，
其余控件文件只"挂 objectName"，不碰颜色。这样主题切换的**一致性由结构保证**，不靠人记。

## 3. 核心决策速览

### 3.0 默认日间，夜间同等完整
首次启动走 **日间**（`UiConfig.theme = "light"`；`theme.normalize()` 遇到非法值也回落日间）。
用户切到夜间后写入 `settings.json` 的 `ui.theme`，重启沿用。
> 夜间不是"附带支持"：底色亮度必须明显低于游戏画面，强调色仍然只在动作用力时出现 ——
> 两套主题按同一标准验收（见 `docs/01` §5.0）。

### 3.1 双主题怎么做到"切了不走样"
```
qss.py（一份模板，几何写死、颜色用 {{token}}）
   ├─ THEMES["dark"]  → 夜间样式表
   └─ THEMES["light"] → 日间样式表
```
- 圆角、间距、字号、选择器**只有一份**；切换只换变量 → 不可能出现"夜里有圆角、日间变直角"。
- `_validate()` 在导入时就检查两张表的键是否完全一致，少一个立刻报错（不给你"日间漏了 hover 态"的机会）。
- `qss.render()` 会检查残留占位符，缺令牌直接抛 `KeyError` —— **宁可启动报错，也不要静默渲染出半透明坏样式**。

### 3.2 日间不是"夜间反色"
| | 夜间 | 日间 |
|---|---|---|
| 底色 | `#0E1216` 近黑 | `#F4F6F8` **冷白灰（不是纯白）** |
| 强调色 | `#2A66F0` 略亮（深底要"跳"） | `#2563EB` 略深（浅底要"沉"） |
| 键位按下 | 绿底 + 近黑字 | 绿底 + 近黑字（**同构**） |

日间底色刻意避开纯白：长期贴屏看，纯白会比纯黑更累；且纯白会与游戏里的白色 UI 抢注意力。

### 3.3 叠加层不跟主题（重要）
检测圈、采样点、按下高亮、框选遮罩压在**游戏画面**上。游戏画面亮度与 App 主题无关 ——
"日间主题下的白色检测圈"在雪地/花海场景里会直接消失。所以它们固定在 `OVERLAY` 表里，
两主题共用。**只有"外框"**（预览留白底、header 胶囊、尺寸标签底板）跟主题走。见 `theme.py` 的注释。

### 3.4 修掉了哪些老问题（对应 `04-UI界面说明` §9）
| # | 老问题 | 处置 |
|---|---|---|
| 1 | 11 个按钮同权重、层级扁平 | **四档按钮体系** + 主操作随运行态迁移（一屏只有一个 accent 填充） |
| 2 | 键位卡在 554px 下挤压 | 卡矮 4px、字号改 px 固定、Δ 接近阈值变琥珀 |
| 3 | 预览叠加 200 个点太密 | 圈 1px/55%、点 45% 且更小，学基线/hover 才提亮 |
| 4 | 状态栏一行 5 段信息过载 | 拆「后端徽标 + FPS + 次要数值」，按宽度优先级丢弃 |
| 5 | 一次性提示与错误在两处跳 | 合并成右侧**单条消息区**（info/warn/error 三语气） |
| 6 | 编辑浮层不像浮层 | 投影 + 指向箭头 + 点击画布关闭 |

## 4. 三条不许破的线（评审时先看这个）

1. **不改可用性矩阵**。档位只决定"长什么样"，不决定"能不能点" —— 两者分离。
2. **不改数据契约**。`tick` 文本语义、谱面 JSON 结构、识别参数一律不碰。
3. **不写死颜色**。QSS 里出现 `#hex`、绘制代码里出现 `QColor(255,...)`，都算 bug。

## 5. 与项目既有约定的对齐

| 既有约定（`docs/04` §11） | 本包怎么守 |
|---|---|
| 窗口 558×913、最小 554 | 全部控件在 538 可用宽内核算过；工具栏反而**更宽松**（去掉 4 个文字标签） |
| 数值必须等宽 | 谱面 / RGB / Δ / 状态栏 / 胶囊全部保留 Consolas |
| 图标全部运行时绘制 | 只改线宽与配色来源，不引位图/iconfont |
| 可用性矩阵与识别流程绑定 | 一行 `setEnabled` 都没动 |
| 不做全局热键 | 未引入 |
