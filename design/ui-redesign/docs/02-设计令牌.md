# 02 · 设计令牌

> **唯一事实来源**：`templates/theme.py` 的 `THEMES` / `OVERLAY` 两张表。
> 本文件是给人看的对照表，`tokens.json` 是给工具/其他 Agent 读的机器版 —— 三者必须一致。
> 新增颜色 = 先加令牌 → 再改模板 → 最后更新本文档；**不许在 QSS 或绘制代码里出现 `#hex`**。
>
> **默认主题 = `light`（日间）**：`UiConfig.theme` 默认值已同步为 `"light"`，
> `theme.normalize()` 对非法值也回落日间。下面的两张表没有主次之分。

---

## 1. 令牌命名规则

| 前缀 | 含义 | 例子 |
|---|---|---|
| `bg-` | 面（背景）。亮度阶梯：`canvas < panel < surface < hover < active`；`input` 是逆阶梯（凹槽） | `bg-panel` |
| `border-` | 线。`subtle` 结构暗示 / `default` 控件边 / `strong` hover 与滚动条 | `border-default` |
| `text-` | 字。`primary` 正文 / `secondary` 区块标题 / `tertiary` 注释数值 / `disabled` 禁用 | `text-tertiary` |
| `accent-` | 主色族。`accent` 填充 / `accent-soft` 淡染底 / `accent-text` 淡底上的字 / `accent-border` 描边 | `accent-soft` |
| `success-` `danger-` `warn-` | 语义色。`-fg` 是该色块上的字色 | `success-fg` |

> **`-fg` 不是"更亮/更暗的版本"，是"画在这个色块上的文字色"**。
> 例如 `success-fg` 在夜间是近黑 `#06140C`（绿底上黑字），日间同样是近黑 —— 因为绿底在两种主题下都要"反色"。

## 3. 对比度实测（WCAG 2.1）

正文要求 4.5:1，大字/图标要求 3:1。下表是**实际计算值**，不是估算：

| 组合 | 夜间 | 日间 | 结论 |
|---|---|---|---|
| `text-primary` / `bg-canvas` | 15.3 | 13.9 | ✓ 远超 |
| `text-secondary` / `bg-panel` | 8.0 | 5.9 | ✓ |
| `text-tertiary` / `bg-panel` | 4.7 | 4.9 | ✓（刚好过线，**不许再调淡**） |
| `accent-fg` / `accent` | 4.9 | 5.1 | ✓ |
| `accent-text` / `accent-soft` | 6.4 | 6.8 | ✓ |
| `success-fg` / `success` | 8.6 | 7.4 | ✓ |
| `danger` / `bg-panel` | 5.4 | 4.8 | ✓ |

> ⚠️ **`text-tertiary` 是这套色板的红线**。它承载 RGB、Δ、帧率等最密集的小字，
> 4.7 已经是"能过 AA 的最淡一档"。任何"再淡一点更高级"的想法都会让 9px 数字不可读。

## 4. 字体

| 用途 | 家族 | 字号 | 字重 |
|---|---|---|---|
| 全局 UI 文案 | `Microsoft YaHei UI` → `Microsoft YaHei` → `Segoe UI` | 12px | 400 |
| 区块标题（键位状态/录制内容） | 同上 | 12px | 600 |
| 次级说明、字段标签 | 同上 | 11px | 400 |
| 按钮 | 同上 | 12px | 400（Primary 为 600） |
| 谱面文本框 | `Consolas` → `Cascadia Mono` | 12px | 400 |
| 键位卡 · 音名/键名 | 同上（等宽） | 11px | 600 |
| 键位卡 · RGB / Δ | 同上（等宽） | 9px | 400 |
| 预览 header、状态栏 | 同上（等宽） | 11px（徽标 10px） | 400 |
| 区域胶囊 | 同上（等宽） | 11px | 400 |

> 为什么键位卡从 7pt（≈9.3px）改成 9px：**不是为了变小，是为了可控**。
> `pt` 受系统 DPI 影响会跳档，`px` 在 125%/150% 缩放下由 Qt 统一换算，卡内三行不会挤成两行。
> 11px 键名 + 9px 微行在 74px 卡宽内是"能全部显示"的上限（`247/242/230` 共 11 字符 × 5.4px ≈ 59px）。

## 5. 焦点态

| 控件 | 表现 | 实现要点 |
|---|---|---|
| 按钮 / 下拉 / 输入框 | 边框色 → `accent`（**宽度不变**，仍 1px） | QSS `:focus { border-color: accent }`。**不能改 width**，否则获得焦点时布局跳 1px |
| 自绘控件（预览、键位卡） | 外描 2px `accent`，外扩 2px | 自绘 `QPen(accent, 2)`，rect 内缩 1px 画 |
| 跳转顺序 | 工具栏行 1→2→3，再 键位区→预览→录制区 | `setTabOrder` 显式声明（见 `04` §3.6） |

> 原实现里按钮多设 `NoFocus`（怕抢文本框焦点）。新规范：**只有试听控制条的图标按钮保持 `NoFocus`**，
> 其余按钮恢复 `StrongFocus` —— 否则键盘用户完全无法操作（可访问性硬伤）。
